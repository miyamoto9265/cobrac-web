## 1. 目的と範囲

CoBRAC Agents は、デスクトップ上の Cursor Agents で行っていた BRA（Brain Reference Architecture）データ作成を、ブラウザから Codex SDK で実行する Web アプリである。

**入力**: ROI（対象脳領域）と TLF（トップレベル機能）。どちらか一方のみでも可（エージェントが調査して補完する）。

**出力**: HCD / FRG の Markdown 中間成果物、5 種 CSV、`.bra.xlsx`、HCD/FRG グラフ JSON。

**初版の範囲外**: プロジェクト共有・共同編集、Web 上での成果物手動編集、課金プラン、モバイルアプリ、独自ドメイン。

## 2. 用語

| 用語 | 意味 |
| ---- | ---- |
| プロジェクト | 1 つの BRA 作成単位。`projectId`（英字始まり 3〜64 文字の英数字・`_`・`-`）で識別 |
| ジョブ | 1 回のワーカー実行。種別は `initial` / `followup`。再開モードは `resume` / `retry` |
| HCD | Hypothetical Component Graph。UC（ノード）と Connection（エッジ） |
| FRG | Function Realization Graph。TLF → GN（`R.`）→ UC（`U.`）の階層 |
| 応答ループ | エージェントが `[QUESTION]...[/QUESTION]` を出したあと、ユーザー回答で再開する仕組み |
| フォローアップ | 完了後に同じスレッドへ修正指示を送り、成果物を再生成するジョブ |

## 3. システム構成

```
ブラウザ (React SPA)
  ├─ Cognito SRP ログイン（ID トークン）
  ├─ CloudFront + S3（静的配信 + /config.json）
  ├─ HTTP API (API Gateway JWT → Lambda / Hono)
  └─ WebSocket API (query token → subscribe project)

Lambda
  ├─ http        REST
  ├─ dispatcher  SQS → ECS RunTask
  ├─ ws          $connect / $disconnect / default
  ├─ broadcaster DynamoDB Streams → WebSocket
  └─ janitor     15 分間隔の死活・タイムアウト

ECS Fargate Spot (1 vCPU / 2 GB)
  └─ Codex SDK ワーカー（1 ジョブ = 1 タスク）
       ├─ DynamoDB（状態・メッセージ）
       ├─ S3（workspace / thread / output / graph）
       ├─ KMS Decrypt（当該ユーザーの API キーのみ）
       └─ OpenAI API（ユーザー各自のキー）
```

パッケージ構成:

| パッケージ | 役割 |
| ---------- | ---- |
| `@cobrac/shared` | 型、CSV パーサ、`buildGraphs()`、Project ID 提案 |
| `@cobrac/api` | Hono アプリと Lambda ハンドラ |
| `@cobrac/worker` | Codex 制御ループ、S3 同期、xlsx / グラフ仕上げ |
| `@cobrac/web` | SPA（認証・チャット・グラフ・設定・管理） |
| `@cobrac/infra` | CDK スタック `CobracAgents` |

## 4. ユーザーと権限

| ロール | 付与条件 | できること |
| ------ | -------- | ---------- |
| user | サインアップ後の既定 | 自分のプロジェクトの作成・実行・閲覧・DL、API キー登録、設定変更 |
| admin | Cognito グループ `admin`、または `COBRAC_ADMIN_EMAILS` に含まれるメールで初回 API アクセス | 上記に加え全ユーザー一覧、無効化/ロール変更、全プロジェクト閲覧、実行中ジョブの強制停止 |

- アカウントはメール + パスワード（Cognito）。セルフサインアップは `COBRAC_SELF_SIGNUP` で切替可能。
- 無効化されたユーザーは API が 403。
- 管理者も自分の OpenAI API キーを登録して使う（システム共通キーは持たない）。

## 6. ワークフロー設計

### 6.1 ステップ

`HCD → FRG → CSV → XLSX`

ステップ状態は `[STEP_COMPLETE] HCD|FRG|CSV` マーカーと、ファイル存在（`8_diagram.md`、`5_FRG作成レポート.md`、5 種 CSV）から導出する。xlsx はワーカーの決定的仕上げで完了とする。

### 6.2 ジョブのライフサイクル

```
POST /projects
  → Projects/Jobs = QUEUED
  → SQS
  → dispatcher（同時実行上限なら 60 秒後に再キュー）
  → ECS RunTask（Spot、失敗時 On-Demand）
  → worker RUNNING
       ├─ [QUESTION] → S3 保存 → WAITING_USER_INPUT → タスク終了
       │     └─ POST /answer → QUEUED → resumeThread
       ├─ 5 種 CSV → FINALIZING → csv_to_excel.py + buildGraphs → COMPLETED
       │     └─ POST /followup → 新ジョブ（同じ thread）
       └─ 失敗 / Spot 中断 / 6h 超過 → FAILED（janitor が最大 2 回自動 retry）
```

### 6.3 実行モード

| mode | きっかけ | プロンプトの要点 |
| ---- | -------- | ---------------- |
| initial | 新規作成 | `instruction_0.md` に従って開始 |
| resume | 質問への回答 | 回答を渡し、中断箇所から再開 |
| followup | 完了後の指示 | フォローアップモード。1 ターン後に仕上げ |
| retry | 失敗/中止の手動再開、または janitor 自動再開 | 既存成果物を残し、未完了分だけ続行 |

### 6.4 ターン制御

1. Codex `runStreamed` で 1 ターン実行し、イベントを Messages に保存する。
2. `[QUESTION]` があれば状態を S3 に書いて終了（課金停止）。
3. initial / retry は 5 種 CSV が揃うまで、成果物一覧付きの続行プロンプトを最大 3 回（`MAX_NUDGES`）。
4. followup は 1 ターン完了で仕上げへ。
5. 連続実行 6 時間で打ち切り。

### 6.5 モデルと reasoning effort

適用順: **プロジェクト指定 → ユーザー既定 → デプロイ環境変数 → Codex 既定**。

- キー登録時に OpenAI `/v1/models` を叩き、gpt-5 系を `availableModels` に保存する。
- 作成画面と設定画面で選択。effort は `minimal` / `low` / `medium` / `high` / `xhigh` / `max` / `ultra` / `persistent`。
- フォローアップ・リトライも同じプロジェクト設定を使う。

### 6.6 エージェントとの約束（instruction）

`prompts/instruction_0.md` ほかに次を定義している。

- ROI / TLF / Project ID / Contributor はプロンプト値を使う。
- ユーザー確認は `[QUESTION]...[/QUESTION]` のみ。そのターンでは作業を止め、回答を待つ。
- 各フェーズ完了時に `[STEP_COMPLETE] HCD|FRG|CSV`。
- xlsx 変換はシステムが行う（エージェントは CSV まで）。

`csv_to_excel.py` は `--contributor` / `--project-id` / `--base-dir` / `--output` で非対話実行する。

## 7. データモデル

正は `packages/shared/src/types.ts`。

### 7.1 DynamoDB

| テーブル | PK | SK | 主な属性 |
| -------- | -- | -- | -------- |
| Users | userId（Cognito sub） | — | email, displayName, contributorName, role, disabled, encryptedApiKey, apiKeyRegistered, apiKeyLast4, availableModels, defaultModel, defaultReasoningEffort |
| Projects | userId | projectId | roi, tlf, contributor, model, reasoningEffort, status, currentStep, stepStates, activeJobId, codexThreadId, pendingQuestion, hasArtifacts, errorMessage, completedAt, **usage, costUsd, usedModels**（全ジョブ合算） |
| Jobs | projectId | jobId | userId, type, status, instruction, pendingAnswer, ecsTaskArn, retryCount, lastHeartbeat, **model, reasoningEffort, usage, costUsd** |

### 7.1 トークン使用量と料金

- `usage` は `{ inputTokens, cachedInputTokens, outputTokens, reasoningOutputTokens }`。ワーカーが Codex SDK の `turn.completed` ごとにジョブに加算し、続けてプロジェクト側を全ジョブから再集計する（`refreshProjectUsage`）。
- `model` はジョブ開始時に実際に Codex へ渡したモデル。プロジェクト作成時に API が **必ず具体的なモデル名に解決**する（リクエスト → ユーザー既定 → `CODEX_MODEL` → `DEFAULT_CODEX_MODEL` = `gpt-5.3-codex`）。「Codex 既定」の不明モデルは残らない。
- `costUsd` は `packages/shared/src/pricing.ts` の単価表（USD / 1M tokens, `PRICING_AS_OF` 日付付き）から `estimateCostUsd()` で算出した **推定値**。式: `(input − cachedInput) × 入力単価 + cachedInput × キャッシュ単価 + output × 出力単価`（reasoning は output に含まれる）。単価表にないモデルは `null` になり UI では `$—` と表示。
- 単価表はコード内の定数。OpenAI の改定時は `PRICING` を直して再デプロイする。実請求は OpenAI ダッシュボードが正。
| Messages | projectId | `{ISO}#{seq}` | jobId, role, type, content, step, meta |
| WsConnections | connectionId | projectId（`_` が接続本体） | userId, ttl |

GSI:

- Jobs `status-index`（status + createdAt）: dispatcher / janitor
- WsConnections `project-index`: 配信先

Streams: Projects / Messages の NEW_IMAGE → broadcaster。

**所有権**: 一般ユーザーは自分の `userId` 配下のみ。Project ID の一意性はユーザー内（同じ ID を別ユーザーが持つことは可能）。

### 7.2 ステータス

プロジェクト / ジョブ共通: `QUEUED` / `RUNNING` / `WAITING_USER_INPUT` / `FINALIZING` / `COMPLETED` / `FAILED` / `CANCELLED`。

### 7.3 S3（成果物バケット）

```
users/{userId}/{projectId}/
  workspace/     # /work/{projectId} の同期（md / csv）
  thread/        # CODEX_HOME/sessions（一覧・DL 対象外）
  output/{projectId}.bra.xlsx
  graph/hcd.json
  graph/frg.json
```

グラフ JSON は LLM 非依存の `buildGraphs()` が CSV から生成する。

## 8. API 仕様

認証: `/health` 以外は Cognito **ID トークン**（`Authorization: Bearer`）。API Gateway JWT オーソライザーが検証する。初回アクセスで Users レコードを作成する。

CORS の OPTIONS は JWT を通さない（Gateway が応答）。`/{proxy+}` は GET/POST/PUT/DELETE/PATCH のみ。

| Method | Path | 説明 |
| ------ | ---- | ---- |
| GET | `/health` | 認証不要 |
| GET / PUT | `/users/me` | プロフィール。PUT は displayName / contributorName / defaultModel / defaultReasoningEffort |
| GET | `/users/me/models` | 利用可能モデルと effort 一覧、既定モデル、単価表にあるモデル一覧 |
| GET | `/users/me/usage` | 自分の全プロジェクトのトークン・推定料金集計（合計 / モデル別 / プロジェクト別） |
| GET / PUT / DELETE | `/projects/{id}/graph/{hcd\|frg}/layout` | グラフのユーザー編集。`{ positions, nodes: { id: {width,height,color,border} }, edges: { id: {lineType,color,width,markers,waypoints,handles,…} } }`。S3 `graph/{kind}.layout.json`。DELETE で既定に戻す |
| GET | `/health` | 認証不要。`{ ok, version, time }` |
| GET | `/users/me/apikey/status` | 登録済みか + 末尾 4 桁 |
| PUT | `/users/me/apikey` | キー登録（OpenAI 疎通後に KMS 暗号化） |
| DELETE | `/users/me/apikey` | キー削除 |
| GET | `/projects` | 自分の一覧（q / status / cursor） |
| GET | `/projects/propose-id` | ROI/TLF から ID 提案 |
| POST | `/projects` | 作成 + 初回ジョブ。API キー未登録は 400、ID 重複は 409 |
| GET | `/projects/{id}` | 詳細 + ジョブ一覧 |
| GET | `/projects/{id}/messages` | チャット履歴 |
| POST | `/projects/{id}/cancel` | 停止 |
| POST | `/projects/{id}/answer` | 質問回答 |
| POST | `/projects/{id}/followup` | 完了後の指示 |
| POST | `/projects/{id}/retry` | FAILED / CANCELLED から再開 |
| GET | `/projects/{id}/artifacts` | 一覧（thread 除外） |
| GET | `/projects/{id}/artifacts/download?key=` | 署名付き URL（15 分） |
| GET | `/projects/{id}/artifacts/text?key=` | md/csv/txt/json の本文 |
| GET | `/projects/{id}/graph/{hcd\|frg}` | グラフ JSON |
| GET | `/admin/users` | ユーザー一覧 |
| PUT | `/admin/users/{id}` | disabled / role |
| GET | `/admin/projects` | 全プロジェクト |
| POST | `/admin/projects/{userId}/{id}/cancel` | 強制停止 |
| GET | `/config` | 同時実行上限など |

WebSocket: `wss://…/prod?token={IDトークン}`。`{action:"subscribe", projectId}` のあと `{type:"message"}` / `{type:"project"}` を受信。

## 9. フロント設計

- Vite + React 18 + React Router + Tailwind。
- 実行時設定は CloudFront の `/config.json`（apiUrl, wsUrl, userPoolId, userPoolClientId, region）。ローカルは `VITE_*`。
- グラフ: `@xyflow/react` + dagre。HCD は ROI 分類でノード色分け、投射の生理的性質（興奮/抑制/修飾）でエッジの既定スタイルを決める。FRG は kind で色分け。ノード検索・ミニマップ・PNG 書き出し・Undo/Redo・グリッドスナップあり。
- ノード: ドラッグで移動、四隅/辺でリサイズ、スタイルパネルで塗りと枠線を変更。
- エッジ: クリックでスタイルパネル。線種（曲線 / 直線 / 直角自動 / **直角・折れ点編集** / 折れ線）、色、太さ、破線、角丸、始点・終点の矢印（矢印・開矢印・四角・丸・ひし形・バー）。直角エッジは線上の「+」で折れ点をいくらでも追加し、ドラッグで曲げ、ダブルクリックで削除。
- 接続位置: 選択中のエッジ両端の丸を、ノード辺上のハンドル（各辺 7 点）へドラッグして起点・終点を変更。
- 抑制性投射の既定: 青色 (`#2563eb`) ＋終点四角。興奮性は灰＋三角、修飾性は紫破線＋丸。分類は Connection コメント優先、なければ送信側の Transmitter / Modulation Type（`classifyEdgeSign`）。同じ分類のエッジへ一括適用できる。
- 配置の保存: `useGraphLayout` が位置・サイズ・色・エッジスタイル（折れ点・ハンドル含む）を 600ms デバウンスで `PUT .../layout` に保存。ノード ID / エッジ ID が同じならグラフ再生成後も維持。Ctrl+Z / Ctrl+Y で取り消し。
- チャットは Markdown（GFM）。コマンド / 思考 / Web 検索は折りたたみ表示。
- 版番号: ルート `package.json` の `version` を Vite の `define` で `__APP_VERSION__` として埋め込み、`git rev-parse --short HEAD` を `__APP_COMMIT__` として併記。運用ルールは `AGENTS.md`。

## 10. ワーカー内部

エントリ: `packages/worker/src/index.ts`。

1. Users / Projects / Jobs を読み、KMS で API キーを復号する。
2. prompts を `/work` にコピー。resume / followup / retry では S3 から workspace と thread を復元する。
3. `createCodex` → `openThread`（`sandboxMode: danger-full-access`、Web 検索 live）。
4. イベントを Messages に書き、ファイル変更のたびに stepStates を更新する。
5. 質問待ち・完了・失敗の直前に S3 へ差分同期する。
6. CSV 完成後に `finalize.ts` が xlsx と graph JSON をアップロードする。

エージェントのシェル環境からは `AWS_*` 認証情報を空にして、タスクロール漏洩を防ぐ。

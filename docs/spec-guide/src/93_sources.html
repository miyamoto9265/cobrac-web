C.2 この文書の作り方

この PDF（docs/CoBRAC_仕様書.pdf）は、docs/spec-guide/ の HTML から作ります。

ファイル役割
src/*.html本文。ファイル名の順に連結する（00_cover が表紙、01_intro が序章、10〜70 が第 1〜7 部、91〜94 が付録）
src/style.cssA4 の版面、部ごとの色、表・囲み・図の書式
build.mjsChromium（Playwright）で PDF にする。目次のページ番号は 2 回の描画で決める。<figure data-figure="…"> に docs/figures の SVG を埋め込み、付録 B を prompts/ から作る
inputs.mjs入力ファイル（本文、取り込む図、プロンプト、差し込み値を読むコード）の一覧と、そのハッシュ
build.json最後に作った PDF の入力のハッシュ・ページ数・バイト数
fetch-fonts.sh本文のフォント（Noto Sans JP、JetBrains Mono）を npm のレジストリから .fonts/ に取る（コミットしない）
  1. 挙動を変えたら、同じ変更の中で該当する節の HTML を直す。数値・上限・ファイル名はコードの定数を確かめて書く。
  2. 1 ファイルだけを確かめるときは node build.mjs --preview src/<ファイル>.html（out/preview-*.pdf）。
  3. 全体を作り直す：リポジトリの直下で npm run spec:build（./fetch-fonts.sh && node build.mjs）。Playwright の Chromium、pdftotext、Python の pypdf が要る。目次のページ番号が本文と合わなければ失敗する。
  4. docs/CoBRAC_仕様書.pdf と docs/spec-guide/build.json をコミットする。npm test（scripts/spec-guide.test.mjs）が、本文・取り込む図・プロンプト・差し込み値のコードが PDF を作った後に変わっていないかを確かめ、変わっていれば作り直しを求める。プロンプトだけを直した場合も、付録 B が変わるので作り直す。
  5. 版を上げた変更を main にマージするとデプロイで API に同梱され、サイトの「仕様書」に出る（第 7 部）。
書き方の約束

です・ます調で、平易で正確な完全文で書きます。列挙できる事実は表にし、識別子は等幅、画面の文言は「」にします。誰が何をするかは、LLM（CoBRAC エージェントなど）・プログラム（ワーカー、API など）・人を区別して書きます。節は <h2 id="s<部>-<番号>"> で、番号を本文に書きます（目次は h1 と h2 から作る）。新しい図は scripts/docs-figures*.mjs で作って data-figure で取り込むか、HTML に SVG を直接書きます。

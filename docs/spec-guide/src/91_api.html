付録 A

API 一覧

CoBRAC Agents の HTTP API と WebSocket のメッセージを、領域ごとにすべて挙げます。HTTP API は API Gateway の HTTP API から 1 つの Lambda（packages/api/src/app.ts、Hono）に渡り、WebSocket は別の API Gateway と handlers/ws.ts・broadcaster.ts が扱います。どちらもプログラムで、LLM は呼びません。

A.1 共通の規則

  • 認証：GET /health 以外のすべてのルートに、Cognito の ID トークン（Authorization: Bearer …）が要ります。API Gateway の JWT オーソライザー（発行元はユーザープール、対象はクライアント ID）が検証し、Lambda はその claims から利用者を決めます。最初のアクセスで Users の項目を作ります。無効にされた利用者は 403（account disabled）です。
  • CORS：事前確認（OPTIONS）は JWT を通さず API Gateway が答えます（どのオリジンも可、ヘッダーは Authorization・Content-Type、メソッドは GET・POST・PUT・DELETE・OPTIONS、1 時間保持）。/{proxy+} のルートは GET・POST・PUT・DELETE・PATCH を受けますが、アプリに PATCH のルートはありません。
  • 所有者の確認：プロジェクトと計画は所有者だけが使えます。ほかの利用者のもの・削除したもの・存在しない ID は、どれも同じ 404 です。Canon は所有者・共同編集者・管理者で使える範囲が違います（第 4 部）。
  • キーとモデル：ジョブを始めるルート（表の「キー」）は、実行に使えるキー（自分のキーか、承認とデフォルトの API キーの組）が無いと 400、利用者が選んだモデルがデフォルトの API キーの Tier に無いと 403 です（1.4）。
  • エラー：状態コードと、短い説明の文（多くは日本語）を本文で返します。予期しないエラーは 500 と { error } です。
コード主な意味
200・201・202成功・作成した・受け付けた（ジョブを積んだ、または積む予定にした）
400入力の誤り、上限の超過、実行に使えるキーが無い、状態に合わない操作の一部
401トークンが無い・無効
403無効にされたアカウント、管理者だけのルート、Tier に無いモデル、PR を受け付けない Canon、コメントできない PR
404存在しない・権限が無い・削除した（区別しない）、BRA-DB の無い環境での登録
409状態の衝突（実行中、ほかの承認が先、同じ処理の重複、計画の更新中のリース「計画を更新中です。少し待ってからやり直してください」など）
502API キーを OpenAI で確かめられなかった

表の「呼べる人」は次の意味です。誰でも：トークン不要。ログイン：ログインしたすべての利用者。所有者：そのプロジェクト・計画・Canon の所有者。共同編集者：Canon の共同編集者。管理者：役割が admin の利用者。「キー」はジョブを始めるルートです。

典拠：packages/api/src/app.ts・lib/auth.ts・lib/http.ts、packages/infra/lib/cobrac-stack.ts

A.11 WebSocket

接続先は wss://…/prod?token={ID トークン}（config.json の wsUrl）です。接続のとき、Lambda のオーソライザーが ID トークンを Cognito の鍵で検証し（tokenUse: "id"、クライアント ID）、通れば ws の Lambda が接続を WsConnections に projectId = "_" の行として記録します（ttl は 2 時間 10 分。API Gateway の接続は 2 時間まで）。切断（$disconnect）では、その接続のすべての行を消します。

向きメッセージ意味
ブラウザ → サーバー{ action: "subscribe", projectId }自分の削除していないプロジェクトを購読する。成功すると { type: "subscribed", projectId } と、いまのプロジェクト { type: "project", … } が返る。見つからなければ { type: "error", message: "project not found" }
ブラウザ → サーバー{ action: "unsubscribe", projectId }購読をやめる
ブラウザ → サーバー{ action: "ping" }接続を保つ（SPA は 5 分ごとに送る）
サーバー → ブラウザ{ type: "message", projectId, message }Messages に新しい行が入った（broadcaster が送る）
サーバー → ブラウザ{ type: "project", projectId, project }Projects の項目が変わった（broadcaster が送る）
サーバー → ブラウザ{ type: "subscribed", projectId }・{ type: "error", message }購読への応答
  • 配信は、プロジェクトの所有者の接続にだけ行います（古いメッセージは、そのジョブの所有者で判断する）。
  • もう無い接続（410 / GoneException）は、送るときに消します。
  • 記録の無い接続からのメッセージは 401、JSON として読めないメッセージと知らない action は 400 です。
  • WebSocket を使うのはプロジェクト画面だけです。計画の画面はポーリングで読み直します（1.5）。

6.15 自律実行

自律実行（英語の画面では Autonomous run）は、計画を人の確認を待たずに最後まで進める、計画の設定です（PlanSettings.autonomous = { maxCostUsd }）。Canon の設定ではなく、オーケストレーターの計画に付きます。目標を渡せば、下書き → 確定 → 各行のプロジェクトの作成 → Canon への push → PR の判断までが、人の操作なしに進みます。ふつうの計画で人を待つ場面（確定・質問・PR の承認・要対応・人の判断）を、下の表のように置き換えます。上限は費用だけです（時間や行の数の上限はありません）。

人を待つ場面ふつうの計画自律実行の計画
下書きの確定所有者が「確定して開始」下書きを適用したステップの直後に、ランナーが確定する（confirmedBy: "runner"）
エージェントの質問質問箱で回答を待つエージェントは質問せず、推奨する選択肢で進む。それでも質問したら、ランナーが定型の回答を返す（3 回まで）
計画の PR人が承認・却下・変更依頼判断のジョブ（AI）が決め、ランナーが所有者の代わりに反映する
要対応（attention）所有者がリトライかスキップ行を見送る（skipped、元の理由は autoSkip）
人の判断（decision）所有者が完了・push・スキップ行を見送る（PR は開いたまま）。ただし計画の Canon が見つからないときは、ふつうの計画と同じく一時停止（canon_missing）
ほかの Canon に入っている既存のプロジェクト人の判断（other_canon）確定のとき既存のプロジェクトを外し、この Canon のために作り直す
再計画の提案（行の追加・削除）承認するまで計画を変えない同じ。計画は提案を待たずに進む（粒度方針の変更は、ふつうの計画と同じく承認なしで反映）

設定

  • 作成：POST /plans に autonomous: { maxCostUsd? } を付けます。自律実行の計画は下書きの作成から始めるので draft: true が必要です（無ければ 400）。費用の上限は 1〜1000 USD（AUTONOMOUS_MAX_COST_RANGE）、省くと 20 USD（AUTONOMOUS_DEFAULT_MAX_COST_USD）。canon を省くと、計画の名前で新しい Canon を作る選択（{ mode: "new", name }）になります。
  • 下書きの間：PUT /plans/{id} { settings: { autonomous: { maxCostUsd } | null } } でオン・オフと上限を変えられます。確定後は変えられません（上限の引き上げは再開で行う）。
  • 画面：新しい計画のフォームの「自律実行」スイッチと費用の上限、「自律実行で開始」（オンのときは「計画を作る」「下書きを作成」の代わりに出る）。下書きの「設定」にも同じスイッチがあります。計画の一覧と計画の画面には「自律実行」の印、確定後の設定には「自律実行: 費用の上限 $n」が出ます。

下書きと確定

  1. 下書き：ふつうの計画と同じく、計画用のジョブが行・アンカー・依存・粒度方針を書きます（6.5）。ジョブが失敗したときは 1 回だけ自動で依頼し直します（PlanJobState.attempt。キーが無いなど所有者の側の理由で始められないときは、やり直さずに下書きに戻す）。
  2. 確定：自律実行の計画で下書きを適用すると、下書きの状態に autoConfirm: true を付け、Lambda のハンドラー（handlers/planRunner.ts の autoConfirm）が、そのステップが計画のリースを返した後に、所有者の確定と同じ関数（confirmPlan）でランナーとして確定します。リースが取れなければ次の分にもう一度試し（ハンドラーは毎分、確定を待つ自律実行の下書きを探す）、ほかの理由で失敗したら理由を autonomousError に残します。画面には「自律実行で下書きを確定できませんでした: …。内容を確かめて「確定して開始」を押してください。」と出て、所有者が手で確定すると消えます。
  3. 下書きができたあとでオンにした計画（autoConfirm が無い）は自動では確定しません。所有者が確定すると、そこから自律実行で進みます。

質問しない

  • エージェントへの指示：自律実行の計画の行のジョブ（作成・リトライ・追加指示）は questionMode: "auto" で積みます。ワーカーは毎ターンの入力に prompts/autonomous.md（付録 B）を足し、エージェントは question で終わらず、推奨する選択肢で同じ作業を続けます（ROI・TLF はそのまま、Canon の定義に合わせる、仮説は足さない）。決めたことは decision_log.md の ## Autonomous decisions に 1 行ずつ、まとめをレポートの ## Limitations に残します。ターンの終わりの JSON（status・message・question）は変えません。
  • 自動回答：それでも質問した行（question）には、実行中の計画のステップの枠の部分で、ほかのジョブより先に、ランナーが定型の回答（AUTO_ANSWER：「推奨した選択肢を採る。無ければ根拠がいちばん確かで、いちばん保守的で戻しやすいものを選び、記録して続ける。もう質問しない」）を、回答の API と同じ関数（answerQuestion、source: "auto"）で返します。再開したジョブは枠を 1 つ使います。回答はジョブの状態を条件に書くので、人の回答と二重になりません。行には「自動回答 n/3」、履歴に row_auto_answered、プロジェクトのチャットに「自律実行: エージェントの質問に自動で回答しました」が出ます。
  • 上限：3 回（MAX_AUTO_ANSWERS）答えたあとにまた質問した行は、見送り（question_limit）にしてから、そのジョブを止めます（チャットに「自律実行の計画がこの行を見送ったため、ジョブを停止しました。」）。

PR の判断

  1. 依頼：自律実行の計画では、review のすべての行（土台の行も、手で push した PR を追う行も）が判断を待ちます（aiReview: "wanted"）。ランナーは空き枠で、AI レビューと同じ関数（requestAiReview）を kind: "decide"・planId つきで、オーケストレーターのモデルと計画の返答言語で所有者として依頼します（1 件 1 枠。canon-review のジョブで reviewKind: "decide"、行の decideAttempts が 1 増える）。手で依頼した AI レビュー（判定なし）が終わった PR にも、判断のジョブを依頼します。
  2. 判断（ワーカー）：材料は AI レビューと同じ（buildCanonAiPacket）で、所見に加えて判定・理由・衝突ごとの選択・依頼する変更を返させます（4.8 の「判断のジョブ」）。材料の文字列はデータとして扱い、指示として従わないよう指示します。
  3. 反映（ランナー、applyDecision）：ジョブが完了したら、PR がまだ開いていることを確かめ、判断と PR の取り込み内容を読み、いまの head に対して差分を取り直して、コードが行き先を決めます（decisionAction）。PR が人の手で決まっていれば、それに従います（6.11）。
AI の判定いまの head に対する差分ランナーの処理行
approveエラーの衝突なし。警告は AI が選んだ側（選ばなかったものと C2b / C8b は canon）、情報は AI が選んだものだけ。それでもブロックする衝突が無いapprovePullRequest（所有者として、名前は「AI (<モデル>)」、理由をメモに）。Canon は新しい rev にdone（row_ai_decided・row_done）
approveエラーの衝突がある（判断の後に Canon が進んでできたものも）、またはブロックする衝突が残るPR に変更の依頼を記録し、Canon に合わせる追加指示（canonFixInstruction：衝突ごとに Canon の値とこのプロジェクトの値を並べる）を用意pending（followup.kind = "fix"）
request_changes—AI が挙げた変更（無ければ理由）で requestPrChanges し、それを追加指示にするpending（followup.kind = "changes"）
reject—rejectPullRequest（理由つき）見送り（ai_rejected）
  • 追加指示：Canon に合わせた更新（6.11）と同じ経路で、空き枠とバッチの順で始まります。プロジェクトを最新の rev に固定し直し、queueFollowup で積みます。題は fix なら「Canon rev N に合わせて更新」、changes なら「Canon PR #n の AI レビューの指摘に対応」で、続けて依頼の本文です。完成すると再び push し、新しい PR が古い PR を置き換えて、また判断します。
  • push の時点のエラーの衝突：ふつうの計画では、Canon が進んでいないのにエラーの衝突があると人の判断ですが、自律実行では fix の追加指示にします（pushOutcome(…, { autonomous: true }) → { to: "conform", fix: true }）。
  • 回数の上限：追加指示（Canon に合わせた更新を含む）は 1 行 3 回（AUTONOMOUS_MAX_FOLLOWUPS。ふつうの計画は 2 回）まで。超えると見送り（conform_limit、PR は開いたまま）。判断のジョブが失敗した・結果が読めないときは依頼し直し、3 回（MAX_DECIDE_ATTEMPTS）で見送り（decide_failed、PR は開いたまま）。
  • 競合：承認の途中で別の承認が Canon を進めた（race）ときは、次のステップで新しい head に対してもう一度反映します。
  • 範囲：判断するのは、その計画が push した PR だけです。同じ Canon へのほかの PR（ほかの人・ほかの計画のもの）は、これまでどおり人が判断します。
  • 記録：判断した人は「AI (<モデル>)」と、判断したジョブとモデル（via）が PR・承認・履歴・rev に残ります（4.8）。PR の画面の「AI レビュー」には「AI の判断」（「AI が承認」「AI が変更を依頼」「AI が却下」、理由、依頼した変更）が出ます。

コードが最後に決める線：AI はエラーの衝突を選べず（incoming を選んでも除く）、エラーの衝突のある PR は取り込まれません。選ばれなかった警告は Canon の値を残します。AI の判定がどうであれ、取り込みは人の承認と同じ approvePullRequest（同じ検査）を通ります。

費用の上限

  • 数える費用（planSpendUsd、推定 USD）：各行のプロジェクトの費用（既存のプロジェクトで済んだ行は数えない）、計画用のジョブ（下書き・再計画）、この計画の PR の canon-review のジョブ（AI レビューと判断）。
  • 上限に達したら：毎ステップ確かめ、初めて達したときに costLimitAt とイベント cost_limit_reached（費用と上限）を記録します。それ以降、新しい行・追加指示・再計画を始めません。実行中の行は最後まで進み、その質問への自動回答と PR の判断も続きます。動いているもの（開始中・実行中・質問中の行、判断を待つ PR）が無くなると、計画は一時停止します（pausedReason: "cost_limit"。画面には「一時停止中: 自律実行の費用の上限に達したため、新しい行を始めていません。上限を上げると再開できます。」）。実行中の行が最後まで進むので、費用は上限を少し超えることがあります。
  • 再開：POST /plans/{id}/resume { maxCostUsd }。新しい上限は 1〜1000 USD で、これまでの費用より大きくなければ 400。設定を書き換え、costLimitAt を消し、イベント cost_limit_raised を残します。上限に達して止まった計画を上限なしで再開しようとすると 400 です。画面では一時停止の帯の下に「新しい費用の上限」と「上限を上げて再開」が出ます。

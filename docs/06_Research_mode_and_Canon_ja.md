# 調査モードと Canon

CoBRAC Agents の 2 つの機能の使い方です。**調査モード**は HCD を作る前に文献を調べる機能、**Canon** は複数のプロジェクトで回路の定義をそろえる機能です。画面には短いラベルと「?」だけを置き、詳しい説明はこのページにまとめています。設計は [01_設計仕様.md](./01_設計仕様.md) の 6.11 と 6.14〜6.19 にあります。

## 調査モード

作成画面のチェックボックスです。既定はオンです。

- **オン**: HCD の前に、エージェントが PubMed と Europe PMC で文献を調べます（トレーサー研究、霊長類とげっ歯類の証拠、層と細胞種）。候補の投射ごとに、見つけた証拠を記録します。ワーカーが調べた範囲を点検し（候補ごとの検索回数、PMID か DOI のある証拠など）、足りなければ 2 回まで補わせます。HCD と FRG はこの調査をもとに作ります。
- **オフ**: これまでどおり、HCD を作りながら Web 検索します。速く安く済みますが、調査は浅くなります。
- **時間と費用**: 選んだモデルでの目安（約 10〜60 分増、追加のトークン分の費用）を画面に出します。概算なので、実際の値は各ジョブの利用量で確認してください。調査は 60 分で打ち切り、それまでに見つかった範囲で HCD に進みます。
- **プロジェクトごとに固定**: 作成後は変えられません。追加指示とリトライも同じ設定で動きます。プロジェクトのヘッダーに「調査モード: オン／オフ」と出ます。

## Canon

**Canon** は、回路の定義をそろえる自分のプロジェクトのまとまりです。同じ Canon の中では、同じ UC Descriptor はいつも同じ Uniform／Collection の区別、同じ分解（Sub-Circuits）、同じ Circuit ID・正式名・性質になります。粒度は Canon ごとに決められます（ネットワーク水準の粗い Canon と、層水準の細かい Canon を並べて持つ、など）。

- 1 つのプロジェクトが入れる Canon は 1 つだけです。
- **粒度方針**: 「新皮質は野 × 投射クラス（IT/PT/CT）、皮質下は核全体」のような一文です。Canon にまだ無い回路は、エージェントがこの方針に沿って作ります。
- **rev（版）**: Canon の中身は、PR を承認したときだけ変わります。承認のたびに新しい rev（rev 1、rev 2…）ができます。rev 0 は空の Canon です。
- Canon の画面には、参加プロジェクト、PR、中身（回路・接続・文献）、rev の履歴が並びます。名前・粒度方針・説明もここで直せます。

### 新しいプロジェクトで Canon を使う

作成画面の「Canon」欄で選びます。

- **なし**: Canon に入れません。
- **既存の Canon**: その Canon に入れます。最初の実行から最新の rev に従います。
- **既存のプロジェクトから新しく作る**: Canon に入っていない完了済みのプロジェクトを、優先する順（上が優先）に選びます。プレビューに rev 1 の中身が出ます。プロジェクトどうしで定義が食い違うときは、どちらの値を使うかを選ぶか、残りをまとめて優先順で決めるか、そのプロジェクトを PR にして保留（または除外）します。

新しいプロジェクトの既定の Canon は設定画面で決められます。

### Canon による生成時の制約

参加プロジェクトは、実行のたびに固定した rev に従います。エージェントは読み取り専用の `canon/` フォルダで Canon の定義を受け取り、その Circuit ID・名前・性質・接続・文献をそのまま使うよう指示されます。

HCD のステップが終わると、ワーカーが結果を Canon と照らし合わせます。**食い違いは修正すべき問題としてエージェントに戻し**、ほかの検査と同じ修正ターンで直させます。対象は次のとおりです。

- 同じ Descriptor が、片方で Uniform、もう片方で Collection になっている
- Collection の分け方（Sub-Circuits）が違う
- Uniform の回路の隣に、同じ部位のより細かい回路がある
- Circuit ID と Descriptor が 1 対 1 に対応していない
- 接続の端が Collection になっている
- 正式名が違う
- 同じ Reference ID が別の論文を指している

これより小さな違い（Sub-Circuits の追加、性質の違い、同じ論文の別 ID、接続の書き方の違い）は、チャットにメモとして出るだけで実行は止めません。Canon で確認済みの文献と引用文は、もう一度照合しません。

この動きはすべての Canon で同じです。以前の「助言（警告だけ）」の設定はなくなり、その設定で作った Canon も同じように動きます。

### rev と更新

プロジェクトのヘッダーに、所属する Canon と従っている rev が出ます（例:「rev 1（最新 2）」）。

- **新しい rev あり**: Canon は進みましたが、このプロジェクトが使う定義は変わっていません。「最新の rev にする」で固定を進めると、次の実行から従います。
- **影響する変更あり**: このプロジェクトが使う定義が変わりました（回路が Collection になった、Sub-Circuits や ID が変わった、など）。「Canon に合わせる」で固定を進め、プロジェクトを直す追加指示を送ります。

## push と PR

- **Canon に push**（完了した参加プロジェクトの画面）: プロジェクトの最新のデータを Canon と比べて **PR（プルリクエスト）** を作ります。Canon の所有者が承認するまで、Canon は変わりません。
- **PR の確認**（Canon の所有者）: PR の画面に、衝突、影響を受けるほかのプロジェクト、変更の一覧が出ます。重い衝突（上の一覧）はプロジェクト側で直すか、Uniform／Collection と分解については取り込む側の定義を採って解決します。要確認の項目は、Canon の値のままにするか取り込む側の値にするかを 1 件ずつ選びます。承認すると次の rev ができます。却下には理由が必要です。送った側は取り下げられます。
- **Canon から Canon へ**: Canon の画面の「別の Canon に PR を送る」から、最新の rev を自分の別の Canon か、ほかのユーザーの公開 Canon（Canon ID は公開ページにあります）に送れます。受け取った側の所有者が同じ規則で確認します。

## 公開ライブラリと複製

- プロジェクト（成果物ができたもの）と Canon は、それぞれの画面で**公開**にでき、いつでも非公開に戻せます。公開すると、ログインした誰でも**公開ライブラリ**で閲覧できます。チャットの履歴・費用・メールアドレスは公開されません。
- **複製**: 公開プロジェクトは、自分の新しい非公開プロジェクトとして写せます（HCD・FRG・表データ・レポート・解説記事）。元のプロジェクトは変わりません。BRA xlsx は追加指示で作り直されます。
- **ほかのユーザーからの PR**: 公開 Canon は、所有者が止めない限り、ほかのユーザーの Canon からの PR を受け付けます。承認するのはいつも所有者です。

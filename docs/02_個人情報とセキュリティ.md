本システムは一般公開サービスではなく、**招待またはセルフサインアップで入る少数の個人利用**を前提とする。それでも OpenAI API キーと研究データを扱うため、保存・復号・ログの扱いを明示する。

---

## 1. 取り扱う情報

### 1.1 個人に結びつく情報

| 情報 | 取得元 | 保存先 | 用途 | 備考 |
| ---- | ------ | ------ | ---- | ---- |
| メールアドレス | サインアップ | Cognito、DynamoDB Users | ログイン、管理者表示 | 必須 |
| パスワード | サインアップ | Cognito のみ | 認証 | アプリ・DynamoDB には置かない |
| Cognito sub（userId） | Cognito | 全テーブルの所有キー、S3 プレフィックス | 識別 | UUID |
| 表示名 / Contributor 名 | 設定画面 | Users、Project.csv / xlsx | プロフィール、成果物の著者欄 | 英語推奨（xlsx 仕様） |
| OpenAI API キー | 設定画面 | Users.encryptedApiKey（KMS 暗号文） | Codex 実行 | 平文は保存しない。API 応答にも出さない |
| API キー末尾 4 桁 | 登録時に算出 | Users.apiKeyLast4 | 「登録済み」表示 | キー本体の代替にはならない |
| 利用可能モデル一覧 | OpenAI `/v1/models` | Users.availableModels | モデル選択 UI | キー登録時のスナップショット |

パスワードハッシュ、MFA 秘密などは Cognito が管理する。アプリは ID / Access / Refresh トークンだけをブラウザで扱う。

### 1.2 プロジェクトデータ（研究・作業成果）

ROI / TLF、チャット全文（ユーザー指示、エージェント出力、コマンド結果、Web 検索クエリ）、中間 Markdown、CSV、xlsx、グラフ JSON、Codex スレッド状態。

これらは「個人情報」ではないが、未公開の研究仮説や文献メモを含みうる。**他ユーザーからは見えない**（管理者はプロジェクト一覧と強制停止が可能。成果物本体の閲覧 API は所有者のみ）。

### 1.3 取らない・返さないもの

- 決済情報、住所、電話番号、生年月日
- API キーの平文（GET `/users/me` は `encryptedApiKey` を落とす）
- `thread/`（Codex セッション）のダウンロード URL

## 2. データの所在

```
ブラウザ
  └─ Amplify: ID/Access/Refresh トークン（ローカル）

Cognito User Pool
  └─ メール、パスワード（ハッシュ）、確認状態、グループ

DynamoDB
  ├─ Users        プロフィール + API キー暗号文
  ├─ Projects     メタデータ・質問文
  ├─ Jobs         実行状態・トークン使用量
  ├─ Messages     チャット全文（60,000 文字で打ち切り）
  └─ WsConnections 接続 ID（TTL 約 2 時間）

S3 Artifacts
  └─ users/{userId}/{projectId}/{workspace,thread,output,graph}/

CloudWatch Logs（保持 14 日）
  ├─ Lambda 標準出力（エラーメッセージ。キーは出さない実装）
  └─ ワーカーログ（コマンド出力の一部が Messages 経由でも残る）

OpenAI
  └─ プロンプト、ワークスペース内ファイル、Web 検索。利用規約に従う
```

リージョンは **ap-northeast-1（東京）**。バックアップ（PITR）は現状オフ。Users / Projects / Jobs / Messages / 成果物バケット / KMS / User Pool はスタック削除しても残る（`RemovalPolicy.RETAIN`）。

## 3. 暗号化

### 3.1 通信経路

| 経路 | 方式 |
| ---- | ---- |
| ブラウザ ↔ CloudFront | HTTPS（HTTP はリダイレクト） |
| ブラウザ ↔ Cognito | HTTPS |
| ブラウザ ↔ HTTP API | HTTPS + Bearer ID トークン |
| ブラウザ ↔ WebSocket | WSS。接続時に query `token` で ID トークン検証 |
| Lambda / ワーカー ↔ AWS API | TLS（SDK 既定） |
| ワーカー ↔ OpenAI | HTTPS（Codex SDK） |

S3 バケットは `enforceSSL`。署名付きダウンロード URL も HTTPS。

### 3.2 保管時

| 対象 | 暗号化 |
| ---- | ------ |
| S3（フロント・成果物） | SSE-S3（S3 マネージド） |
| DynamoDB | サービス既定の保管時暗号化 |
| ECS エフェメラルディスク | Fargate 既定 |
| Cognito パスワード | Cognito 管理（アプリは平文を保持しない） |
| OpenAI API キー | **顧客管理 KMS キー（CMK）で Encrypt**。DynamoDB には base64 暗号文のみ |

成果物バケットに追加の KMS-SSE はかけていない。オブジェクトは非公開（Block Public Access + OAC はフロント用バケット）。成果物は署名付き URL（15 分）でのみ取得する。

### 3.3 API キーの KMS 詳細

- キー種別: カスタマーマネージド対称 CMK。年次ローテーション有効。削除ポリシー RETAIN。
- Encrypt（API Lambda のみ）: `EncryptionContext = { userId, purpose: "openai-api-key" }`
- Decrypt（ワーカーのみ）: 同じコンテキスト必須。別ユーザーの暗号文はコンテキスト不一致で復号できない。
- 平文の寿命: 登録時は検証リクエストのメモリ内のみ。実行時はワーカープロセスのメモリと Codex プロセスへ渡る。ディスク・ログ・S3 には書かない。
- 削除: `encryptedApiKey` を空にし、`apiKeyRegistered=false`。KMS 側の過去暗号文は残るが参照されなくなる。
- 登録時検証: `GET https://api.openai.com/v1/models`。401/403 なら拒否。

**ブラウザからキーを再取得する API はない。** 忘れた場合は OpenAI 側で再発行して上書き登録する。

### 3.4 暗号化していないもの（意図的）

チャット本文、ROI/TLF、成果物、グラフ JSON、スレッド状態は S3/DynamoDB のサービス暗号化のみ。アプリレベルのフィールド暗号化はしていない。管理者や AWS アカウント権限者はコンソールから読める。

## 4. 認証と認可

### 4.1 認証

- Cognito User Pool。サインインは **SRP**（パスワードをサーバに直接送らない）。
- パスワード方針: 10 文字以上、英小文字 + 数字必須。
- トークン寿命: ID / Access 2 時間、Refresh 30 日。
- `preventUserExistenceErrors`: 存在しないメールでもエラーを揃える。
- アカウント回復: メールのみ。
- セルフサインアップ無効時は管理者が Cognito でユーザー作成する。

### 4.2 API 認可

1. API Gateway JWT オーソライザーが ID トークンの iss / aud を検証する。
2. Hono が claims から userId / email / groups を取り、Users を読む。
3. プロジェクト操作は `getProject(自分の userId, id)` のみ。他人の ID を指定しても 404。
4. S3 キーは `users/{自分}/{projectId}/` に固定。`..` と `thread/` と絶対パスは拒否。
5. admin ルートは `role === "admin"`。自分自身の無効化は不可。

### 4.3 WebSocket

- `$connect` 前に Lambda オーソライザーが ID トークンを検証する。
- subscribe 時も当該ユーザーのプロジェクトか確認する。
- 接続行は TTL 付き。切断で削除。410 Gone は購読解除。

### 4.4 CORS

プリフライト（OPTIONS）は JWT を通さない。許可ヘッダは `Authorization` と `Content-Type`。オリジンは現状 `*`（個人利用・CloudFront 既定 URL 前提）。独自ドメイン化する場合はオリジンを絞る。

## 5. ワーカーの隔離

| 項目 | 実装 |
| ---- | ---- |
| 実行単位 | 1 ジョブ 1 タスク。他ジョブのディスクは共有しない |
| OS ユーザー | uid 10001 `worker`（非 root） |
| ネットワーク | パブリックサブネット + パブリック IP。インバウンドなし、アウトバウンド許可（OpenAI / AWS / 文献 Web） |
| Codex sandbox | コンテナ自体を境界とみなし `danger-full-access` + `approvalPolicy: never`（コンテナ内 Landlock は使えない） |
| AWS 認証情報 | エージェント子プロセスの環境から `AWS_ACCESS_KEY_ID` 等とコンテナ認証 URI を空にする |
| 使えるキー | ジョブの userId で復号した 1 本のみ |
| 権限 | タスクロールは Users/Projects/Jobs/Messages の読み書き、成果物 S3、**KMS Decrypt のみ**（Encrypt は API） |

エージェントは Web 検索と任意コマンドを実行できる。プロンプトインジェクションでワークスペース外やメタデータを読もうとするリスクは、AWS 認証情報の除去と「ユーザー所有データのみ」で緩和している。完全な多テナント隔離（別アカウント / 別 VPC）ではない。

## 6. 外部送信（OpenAI ほか）

ジョブ実行中、次がユーザーの API キー経由で OpenAI に送られる。

- ROI / TLF / Contributor / Project ID
- instruction 全文と、エージェントが読んだワークスペースファイル
- ユーザーの回答・フォローアップ
- エージェントが発行した Web 検索クエリ（検索プロバイダへ）

**OpenAI 側の保持・学習・リージョンは OpenAI の契約・組織設定に従う。** 本アプリはゼロデータリテンションを強制しない。機密文献を扱う場合は利用者の OpenAI 組織設定を確認すること。

キー登録時の `/v1/models` も同じキーで OpenAI に届く。

## 7. ログと監査

| 場所 | 残りうるもの | 残さないもの |
| ---- | ------------ | ------------ |
| Messages | プロンプト、エージェント文、コマンド出力（長い場合は前後を切る）、エラー | API キー |
| CloudWatch | 例外メッセージ、タスク ARN、モデル名 | キー平文（実装上出力しない） |
| S3 thread/ | Codex セッション（再開用） | — |

保持: ログ 14 日。Messages / 成果物は無期限（削除 API は初版なし。一覧から消す機能も未実装）。

管理者操作（無効化・強制停止）は専用の監査テーブルを持たない。Jobs / Messages の system 行が痕跡になる。

## 8. 脅威と対策

| 脅威 | 対策 | 残るリスク |
| ---- | ---- | ---------- |
| 他人のプロジェクト閲覧 | userId スコープ、署名 URL も自分のプレフィックスのみ | 管理者と AWS 権限者はメタデータを見られる |
| API キー窃取（DB 漏洩） | KMS + EncryptionContext。平文 API なし | 復号権限を持つワーカーロール侵害時 |
| API キー窃取（ログ / エージェント） | ログに出さない。子プロセスから AWS 認証を除去 | エージェントがキーをファイルに書く可能性は残る |
| 未認証 API | JWT オーソライザー。CORS プリフライトは認証対象外 | `/health` は公開 |
| アカウント列挙 | Cognito `preventUserExistenceErrors` | メール確認の有無は別途推測しうる |
| Spot 中断で中途半端な成果 | S3 永続化 + janitor 自動リトライ | 最大 2 回。それ以上は手動 |
| 長時間放置の質問待ち | 7 日で FAILED | 成果物は S3 に残る |
| セルフサインアップ悪用 | `COBRAC_SELF_SIGNUP=false` で閉じられる | 既定は開放。課金は被害者の OpenAI キー次第（未登録ならジョブ不可） |

## 9. 運用上の注意

1. **チャットやチケットに API キーを貼らない。** 漏れたら OpenAI で無効化し、設定画面で再登録する。
2. 管理者メールは `.env` の `COBRAC_ADMIN_EMAILS`。リポジトリにコミットしない（`.gitignore` 済み）。
3. 不要ユーザーは管理画面で無効化する。Cognito ユーザー削除はコンソール作業。
4. スタック削除しても Users / 成果物 / KMS / User Pool は残る。破棄するときは手動で空にしてから消す。
5. CloudWatch にコマンド出力が残ることがある。機微をプロンプトに書かない。
6. 本番でオリジン制限・PITR・S3 の KMS-SSE・アクセスログを足す余地はある（未実装）。

## 10. 利用者への短い説明

- メールとパスワードは AWS Cognito が保持する。
- OpenAI API キーは AWS KMS で暗号化され、ジョブ実行時だけ復号される。画面に再表示されない。
- 作成した BRA データは自分のアカウントにだけ紐づく。料金は自分の OpenAI アカウントに請求される。
- エージェントは文献調査のためインターネットと OpenAI にデータを送る。
- 一般公開の SNS 的サービスではなく、関係者向けの作業環境である。

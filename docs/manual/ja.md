# CoBRAC Agents 利用マニュアル

CoBRAC Agents を使って BRA（Brain Reference Architecture）データを作る人のための手引きです。はじめての方は「できること」と「はじめに」を読めば、最初のプロジェクトを実行できます。そのほかの節は、必要になったときに目次から開いてください。画面の「?」にも短い説明があります。

## できること

ROI（対象領域）と TLF（トップレベル機能）を入れて実行すると、AI エージェントが文献を調べながら BRA データを作ります。作業はサーバーで進むので、ブラウザを閉じても止まりません。

![ROI と TLF から BRA データまでの流れ](./figures/manual-overview.ja.svg "ROI と TLF から BRA データまで。各ステップが終わると成果物が画面に出ます")

- **HCD**（回路の図）: 領域の回路（UC）と、その間の接続を、根拠の文献とともにまとめます。
- **FRG**（機能の分解）: TLF を、グループ（GN）を経て UC まで分解した木です。
- **CSV と BRA xlsx**: HCD と FRG から作る提出用のデータです。xlsx は CoBRAC の形式と、公式テンプレート Template-v2-2 の形式の 2 種類を出せます。
- エージェントが判断に迷うと質問が来ます。答えると作業が続きます。完了した後は、追加の指示で直せます。
- 1 件の作成には数十分から数時間かかり、OpenAI の利用料がかかります（[費用](#費用はどこで見る)）。
- 多くのプロジェクトをまとめて作るときは、[CoBRAC オーケストレーター](#cobrac-オーケストレーター) で計画にして、順番に自動で実行できます。

## はじめに

![使い始めるまでの 4 つの手順](./figures/manual-start.ja.svg "アカウント作成から最初のプロジェクトまで")

### アカウントを作る

1. ログイン画面の「アカウントを作成」で、メールアドレスとパスワード（10 文字以上）を入れます。
2. メールに届いた確認コードを入れると、ログインできるようになります。コードが届かないときは「コードを再送」を押してください。
3. パスワードを忘れたときは、ログイン画面の「パスワードを忘れた」から再設定します。

アカウントの作成を受け付けていない場合は、管理者に相談してください。

### API キーを用意する

エージェントの実行には OpenAI の API キーが要ります。どちらか一方を用意します。

- **自分のキー**: 「設定」の「OpenAI API キー」に貼り付けて「登録 / 更新」を押します。OpenAI に接続を確かめてから、暗号化して保存します。利用料は自分の OpenAI アカウントに請求されます。
- **デフォルトの API キー**: 自分のキーが無い場合は、管理者に利用の承認を依頼してください。承認されると、設定画面に「デフォルトの API キーを利用中」と出ます。モデルの一覧には、このキーで使えるモデルだけが出ます。

両方ある場合は、自分のキーが優先されます。

## プロジェクトを作る

サイドバーの「新規プロジェクト」を開きます。

1. **ROI** に脳の領域を、**TLF** にその領域が担う機能を書きます。片方だけでも作れます。ROI に Brainnetome の略称や英語の領域名を打つと候補が出ます。「例を使う」で入力例が入ります。
2. 必要に応じて、入力欄の下のボタンで設定します。
   - 「+」: 参考資料（PDF・画像・テキスト・Office ファイル、URL）を添付します。ファイルは 10 個・合計 50 MB（1 ファイル 20 MB）まで、URL は 20 件までです。エージェントは参考にしますが、文献と引用は公開文献で確かめます。
   - 「Canon」: 回路の定義をそろえたいときに選びます（[Canon を使う](#canon-を使う)）。
   - 「v」: モデル、reasoning effort、調査モードを選びます（[調査モードとモデル](#調査モードとモデル)）。
   - 「仮説モード」: 入力欄の下端、Canon の隣にあるチェックです。チェックを入れると、文献が直接は裏付けない接続や UC を仮説として含められ、入力欄の下に設定が開きます。「?」に触れると説明が出ます（[仮説モード](#仮説モード)）。
3. 「実行」を押します。ROI で Enter を押すと TLF に移り、TLF で Enter を押すと実行します（Shift+Enter は改行）。

プロジェクト名は自動で付き、あとでプロジェクト画面で変えられます。Contributor 名は設定画面の値が使われます。

### 調査モードとモデル

- **調査モード**（既定はオン）: HCD を作る前に、PubMed と Europe PMC で文献を詳しく調べます。時間と費用が増えます（目安は画面に出ます）。オフにすると、HCD を作りながら Web 検索するだけになり、速く安く済みますが、調査は浅くなります。作成後は変えられません。
- **モデルと reasoning effort**: 既定は設定画面で決めた値です。reasoning effort は high を推奨します。

## プロジェクト画面とエージェント

実行するとプロジェクト画面に移ります。サイドバーの「履歴」と「プロジェクト一覧」からも開けます。

![プロジェクト画面の構成](./figures/manual-workspace.ja.svg "ヘッダーと進み具合、成果物のタブ、エージェント欄（PC では右、スマホではボタンで開く）")

- **ヘッダー**: 名前（押すと変更できます）、状態、ROI と TLF、モデル、利用量、参考資料が並びます。スマホでは「詳細」で開きます。
- **進み具合**: 調査 → HCD ⇄ FRG → CSV → xlsx のどこまで進んだかを示します。
- **タブ**: HCD・FRG・表データ・レポート・判断ログ・解説記事・版を切り替えます。まだできていない成果物のタブは薄く表示されます。
- **エージェント欄**: 作業のログ、質問、入力欄です。タブの右端の「エージェント」ボタンで開閉します。

### 状態

| 状態 | 意味 |
| ---- | ---- |
| 待機中 | 作業を始める順番を待っています |
| 実行中・仕上げ中 | エージェントが作業しています |
| 回答待ち | エージェントが質問しています。答えると再開します |
| 完了 | BRA データができました。追加の指示で直せます |
| 失敗・中止 | 止まりました。「続きからリトライ」で再開できます |

### 質問に答える

質問はエージェント欄の最後に黄色の枠で出ます。選択肢がある場合は、ボタンを押すと入力欄に入ります。入力欄に答えを書いて送ると、作業が再開します（Enter で送信、Shift+Enter で改行）。回答は 7 日間待ちます。

### 追加の指示

完了したプロジェクトは、エージェント欄の入力欄から直したい内容を指示できます（例:「○○の UC を追加して、接続を見直してください」）。指示は新しいジョブとして実行され、利用料がかかります。入力欄の下の「この指示で仮説を許す」については[仮説モード](#仮説モード)を見てください。

### 停止とリトライ

- 実行中は、ヘッダーの「停止」で止められます。
- 失敗・中止したプロジェクトは、「続きからリトライ」で前回の成果物から再開します。
- サーバーの都合で作業が途切れた場合は、自動で再開します。1 回のジョブは 6 時間で打ち切られるので、その場合もリトライで続けてください。
- 要らなくなったプロジェクトは、ヘッダーのごみ箱のボタンで削除できます（実行中は先に停止します）。

## 成果物を読む

成果物は、各ステップが終わるとタブに出ます。

### HCD グラフ

- ノードは回路（UC）、矢印は接続です。色で ROI 内と ROI 外（入力側・出力側）を区別し、抑制性の接続は青い線と四角の矢じりで描きます。
- ノードや矢印を選ぶと、詳細のパネル（名前、性質、接続、根拠の文献と引用）が開きます。
- 点線の枠は Collection（1 つの回路を分けてできた UC のまとまり）です。「その他」のメニューで表示を切り替えられます。
- ドラッグで配置を変え、「スタイル編集」で色や線を変えられます。変更は自動で保存されます。PNG で保存することもできます。

### FRG グラフ

TLF から GN を経て UC までの木です。子ノードは折りたたみ・展開できます。UC を選ぶと「HCD でこの UC を表示」で HCD の同じ回路に移ります。GN を選ぶと、その配下の UC を HCD で強調表示できます。

### 表データ・レポート・判断ログ

- **表データ**: 5 つの CSV を表で見られます。見出しを押すと並べ替え、上の欄で行を絞り込めます。元のファイルもダウンロードできます。
- **レポート**: エージェントがまとめた作業の報告です。
- **判断ログ**: どこで何を判断し、なぜそうしたかの記録です。

### BRA xlsx

完成すると、ヘッダーに 2 つのダウンロードボタンが出ます。

- **BRA xlsx**: CoBRAC の形式です。
- **BRA xlsx (Template-v2-2)**: 公式テンプレートの形式です。

### 版

実行やフォローアップが終わるたびに、その結果を変わらない版（v1、v2、…）として残します。「版」タブには、日時、モデル、変わった行の数とともに一覧が出ます。版を選ぶと、次のことができます。

- その版の表を開く
- 別の版と比べて、追加・削除・変更された行を見る

版を残す仕組みの前に完成したプロジェクトは、現在のデータを「未保存」として表示します。次のフォローアップが、変更を始める前にそれを版として保存します。

BRA-DB がある環境では、保存済みの版に **BRA-DB** 欄が出ます。BRA-DB にどの版が入っているかが表示され、「v<n> を BRA-DB に登録」でその版を BRA-DB に登録できます。BRA-DB には登録のたびの記録（どの版か、内容のハッシュ、誰がいつ）が残ります。同じ内容をもう一度登録しても何も変わりません。BRA-DB にあるものより回路や接続が少ない版は、確認してから登録します。

## 仮説モード

既定では、BRA に入れる接続と UC は、文献が直接裏付けるものだけです（「文献の裏付けのみ」）。「仮説モード」をオンにすると、文献が直接は裏付けない接続や UC の性質を、**仮説**と明示して含められます。仮説にも、照合できる前提の論文が 1 件以上必要です（ほかの研究で知られていること、相同な領域の報告など）。引用・DOI・SABRA の境界などの検査は今までどおりです。

### 選び方

- **作るとき**: 入力欄の下端（Canon の隣）の「仮説モード」にチェックを入れます（「?」に触れると説明が出ます。スマホでは「H」の印だけが出ます）。入力欄の下に設定が開きます。仮説にしてよい主張（接続があること・向き・符号、UC の細胞集団・伝達物質と修飾・役割）と、割合の上限を選べます。どこで仮説が要りそうかを一文（200 文字まで）で書くこともできます。範囲はグラフ全体です。
- **追加の指示で**: エージェント欄の入力欄の下の「この指示で仮説を許す」をオンにします。主張の種類、対象（「全体」か「グラフで選んだ回路・GN」）、上限を選んで送ります。対象を絞るときは、先に HCD か FRG のグラフで回路・Collection・GN を選んでおきます。送るとスイッチはオフに戻ります。
- 指示の文に「仮説でよい」と書くだけでは、仮説は許されません。必ずスイッチで指定します。

選んだ主張と対象は「範囲」（S1、S2、…）として記録され、エージェントはその内側でだけ仮説を置きます。仮説が 1 件も無い結果で完了すると、プロジェクトは「文献の裏付けのみ」に戻ります。

### 上限

接続と UC のそれぞれで、仮説の数が全体のこの割合（10%・20%・30%・50% から選ぶ。既定は 20%）を超えると、エージェントに差し戻されます。ちょうど上限なら通ります。追加の指示で上限を変えることもできます。

### グラフと画面の見方

- **HCD グラフ**: 仮説の接続は短い点線と線の中央の「H」、向きだけが仮説の接続は白抜きの矢じり、仮説の UC は点線の枠と「H」で描きます（Collection の枠は破線です）。「H」に触れると仮説の番号（H1、H2、…）が出ます。ツールバーの「仮説を隠す」で、証拠だけのグラフにできます。
- **FRG グラフ**: 仮説に依存する GN に小さな「H」が付き、触れると依存する仮説の番号が出ます。
- **詳細のパネル**: 「根拠: 仮説（相同）」のように根拠の種類と、理由、前提の論文を出します。
- **ヘッダーと一覧**: 「仮説モード」の印と、最新の版の仮説の件数が出ます。
- **版**: 生成条件に、根拠の扱い、範囲、接続と UC の「仮説の件数 / 全件数（割合）・上限」が出ます。
- **Canon**: 仮説は Canon の共有の定義に入りません。push の画面に「仮説 n 件（共有層に入れない）」と出ます。

### BRA-DB

仮説を含む版は、いまは BRA-DB に登録できません（版の BRA-DB 欄のボタンが押せず、理由が出ます）。仮説を登録する規則は別に決まる予定です。仮説が 0 件の版は今までどおり登録できます。

### 次の調査は提案しない

仮説は、BRA に何が含まれているかを示すためのものです。このツールは、仮説を確かめるための調査・実験・予測を提案しません。仮説をどう扱うかは研究者が決めます。仮説を減らしたいときは、追加の指示で「H3 を外してください」「H3 の根拠を探して置き換えてください」のように頼めます。

## 解説記事

BRA データが完成したら、「解説記事」タブで、選んだ言語の図入りの解説記事を作れます。

1. 「記事の言語」とモデルを選び、「解説記事を作成」を押します。数分かかり、利用料はこのプロジェクトに加算されます。
2. できた記事は「表示する言語」で切り替えて読み、.md でダウンロードできます。
3. 記事の後で BRA データが変わると、言語のボタンに印が付きます。「解説記事を作り直す」で最新のデータを反映します。

図は BRA データから描き、引用するのはこのプロジェクトの参考文献だけです。

## Canon

**Canon** は、複数のプロジェクトで回路の定義をそろえるための、自分のプロジェクトのまとまりです。同じ Canon の中では、同じ回路はどのプロジェクトでも同じ ID・名前・分け方になります。

### Canon を使う

- サイドバーの「Canon」で「新しい Canon」を作り、名前と粒度方針（例:「新皮質は野 × 投射クラス、皮質下は核全体」）を書きます。既存のプロジェクトを「プロジェクトを追加」で入れられます。
- 新しいプロジェクトでは、作成画面の「Canon」ボタンで「既存の Canon」を選ぶか、「既存のプロジェクトから新しく作る」を選びます。
- 1 つのプロジェクトが入れる Canon は 1 つだけです。設定画面で、新しいプロジェクトの既定の Canon を決められます。

### Canon に従って作る

Canon に入ったプロジェクトは、Canon の定義（回路の ID・名前・分け方・接続・文献）に従って作られます。Canon と食い違う箇所は、エージェントに直させます。Canon にまだ無い回路は、粒度方針に沿って作ります。

### push と審査

![Canon の基本の流れ](./figures/manual-canon.ja.svg "push で PR を作り、所有者か共同編集者が承認すると新しい rev ができます")

1. **push**: 完了した参加プロジェクトの画面で「Canon に push」を押すと、差分を確かめて PR（プルリクエスト）を作れます。承認されるまで Canon は変わりません。
2. **審査**: Canon の所有者か共同編集者が、PR の画面の 4 つのタブで確かめます。
   - 変更: 今の Canon と承認後を並べた図と、変更の一覧
   - 検査: 決める必要がある衝突と、システムの検査の結果
   - AI レビュー: モデルが食い違いを理由と根拠付きで挙げます（判断はしません）
   - 履歴: だれがいつ何をしたか
3. **判断**: 「承認」すると Canon に新しい rev（版）ができます。承認は 1 人で足ります。「変更を依頼」すると、送った人が直して push し直すまで PR は開いたままです。「却下」すると PR を閉じます。
   - **まとめて承認**: Canon の画面の PR の一覧で、矛盾も要確認の項目も無い未処理の PR（変更を依頼したものは除く）にチェックを入れ、「まとめて承認」を押すと、選んだ PR を番号の順に 1 件ずつ承認します。1 件ごとに、その直前の承認でできた最新の Canon と照らし合わせ直し、矛盾が出た PR（または処理済み・見つからない PR）で止めます。残りは承認しません。結果の行に、承認した件数と、どの PR でなぜ止めたかが出ます。承認した人は、1 件ずつ承認したときと同じように各 PR と rev に記録されます。

**共同編集者**: Canon の所有者は、Canon の画面で、登録済みのメールアドレスを入れて共同編集者を追加できます。共同編集者は「共有された Canon」から開き、PR の審査ができます。設定や削除は所有者だけができます。

### rev に追従する

プロジェクトのヘッダーに、従っている rev が出ます（例:「rev 1（最新 2）」）。

- **新しい rev あり**: 「最新の rev にする」で、次の実行から新しい定義に従います。
- **影響する変更あり**: このプロジェクトが使う定義が変わりました。「Canon に合わせる」で、プロジェクトを直す追加の指示も送ります。

## CoBRAC オーケストレーター

**CoBRAC オーケストレーター**（旧称 BRA Planner）は、作りたい BRA プロジェクト（ROI × TLF）を「計画」にまとめて、まとめて作る機能です。計画を確定すると、同時実行数の上限の範囲で、行を「バッチ」ごとに自動で実行します。目標と資料から、計画の下書きを書かせることもできます。確定するまでプロジェクトは作られません。確定前に実行されるのは「下書きを作成」のジョブだけで、その費用は記録されます。

### 計画を作る

1. サイドバーの「CoBRAC オーケストレーター」で、名前と目標（例:「言語の BRA を一通りそろえたい」）を入れます。
2. 資料のファイル（CSV・TSV・テキスト・xlsx・PDF、10 個まで）を追加するか、行を貼り付けます。1 行が 1 プロジェクトです。CSV・TSV・テキストは、計画を作るときにすぐ行として読み込みます。見出し行があれば ROI（脳領域）、TLF（機能・能力）、理由（備考）、バッチ（列名は「波」でも読めます）、優先度の列を名前で読みます。見出し行が無ければ、1 列のときは TLF、2 列以上なら ROI・TLF・理由の順です。
3. 「計画を作る」は、読み込んだ行で計画を作ります。「下書きを作成」は、計画を作ると同時に下書きを依頼します（目標・ファイル・貼り付けた行のどれかが必要です）。xlsx と PDF の中身は、「下書きを作成」のジョブが読みます（計画を作ったあとで押しても読みます）。
4. 読めなかった行（ROI も TLF も無い、同じ ROI × TLF の行がある、など）は、ファイル名・行番号と理由が画面に出ます。直して「CSV を読み込む」で追加できます。

### 下書きを作成する

- 「下書きを作成」を押すと、計画用のジョブが目標・資料・いまの行を読み、行（ROI × TLF と理由）、アンカー、依存関係、粒度方針を書きます。資料は項目ごとに 1 行にし、「言語の BRA を一通りそろえたい」のような広い目標なら 8〜15 行ほどを挙げます。いまある行は残り、ROI と TLF は変わりません。
- 書いている間、計画は「下書き作成中」になり、行を編集できません。バナーにジョブの状態（ジョブの空きを待っています / 開始を待っています / 実行中）と経過時間が出ます。ジョブは同時実行数の枠が空いてから始まり、ふつうは数分で終わります（1 回のジョブには 7 分の時間制限があります。xlsx・PDF の資料を読む下書きや、20 行を超える下書きは 25 分までです）。「下書きを取り消す」で止められます。
- 終わると下書きに戻り、行を自由に直せます。読めなかった項目（xlsx や PDF の行、目標の一部など）は、ファイル名・場所・理由の一覧で出ます。必要なら手で行を足してください。存在しない行・アンカー・プロジェクトを指していた部分は使われず、その件数が出ます。失敗したときは理由が出ます。
- **粒度方針**は、この計画の行が回路をどの細かさで定義するかの方針です（例:「新皮質は領域 × 投射の種類、皮質下は神経核」）。粒度方針は オーケストレーターが決めます。下書きのジョブが書き、確定後は再計画のジョブが行の結果を見て変えることがあります。あなたが書いたり編集したりする欄はありません。
- **費用**: 下書きのジョブも通常のジョブと同じく、同時実行数の枠を 1 つ使い、あなたの API キー（またはデフォルトの API キー）で実行され、費用が記録されます。短い 1 回の実行なので、行のプロジェクトに比べればわずかです。取り消したジョブや時間切れのジョブも、それまでに使った分の費用は記録されます。「下書きを作成」は何度でも押せますが、そのたびにジョブが実行されます。

### 行とバッチを整える

- 下書きの間は、行の追加・削除・並べ替え、ROI・TLF・理由・バッチの変更ができます。「N 件ずつのバッチに分ける」は、いまの並び順のまま、同時に実行できる数（N）ずつバッチに分けます。
- 次のバッチは、いまのバッチの行がすべて「開始待ち」でも「実行中」でもなくなってから始まります。質問中や要対応の行は待たれません。
- 「設定」で、**オーケストレーターのモデル**と **エージェントのモデル**を別々に選べます。オーケストレーターのモデルは、オーケストレーター自身のジョブ（下書きの作成、バッチのあとの再計画、行の PR の AI レビュー）に使います。エージェントのモデルと推論の強さは、各行の BRA プロジェクトを作るエージェントに使います。どちらも「デフォルト」のままなら、確定したときに設定のデフォルトのモデルに決まります。ほかに調査モードも決められます。どの行も、この設定と確定した時点のハーネスルールで作られます。確定後は変えられません。

### 種のバッチとアンカー

- 下書きの行には**アンカー**が付きます。アンカーは、その行の ROI と、主な入力元・出力先の領域を、SABRA（BNA と DHBA を組み合わせたアトラス）の単位で表した ID です（BNA の領域は `BNA:57-58`、DHBA の領域は HOMBA の ID で `HOMBA:12261` のように書きます）。下書きのジョブが RCS で調べて付けます。行には最初の 4 個と残りの数が出ます。
- 「ハブ n」は、アンカーを共有するほかの行の数です。「重なり」は、アンカーを 2 個以上共有する行です。同じ回路を作ることになるので、同じバッチには入れません。「依存」は、その行が組み合わせて作る元の行です（たとえば「復唱」は「音韻処理」と「発話」から作ります）。依存する行より後のバッチに入ります。領域を共有するだけでは依存ではありません。そうした行はアンカーで別のバッチに分けます。
- **「種」**は、ほかの多くの行とアンカーを共有する行（最大 3 行）です。ほかの行より先に、1 件ずつ、それぞれ自分のバッチで作ります。多くの行が使う回路を先に 1 回だけ組み立てておき、あとの行がそれを使えるようにするためです。種の行のバッチの見出しには「種」と出ます。
- 残りの行は、依存する行のあとで、同時実行数に収まり、重なる行がいない、いちばん早いバッチに入ります。
- 「自動で並べる」は、アンカーと依存関係からバッチと種を決め直します（ジョブは使わず、費用はかかりません）。下書きを作成した直後も、この順序になっています。
- 行を足す・消す・入れ替える、またはバッチを変えて保存すると手動の順序になり、あなたが決めたバッチがそのまま使われます（バッチのあとの並べ直しもしません）。理由・ROI・TLF や「作り直す」だけを変えた保存では、順序はそのままです。自動の順序の下書きに「CSV を読み込む」で行を足したときは、全体をもう一度自動で並べます。自動の順序の計画は、確定するときに、その時点の同時実行数でもう一度並べます。

### 既存のプロジェクト

- 同じ ROI × TLF の完成したプロジェクトがすでにあると、その行に「既存」が付き、そのプロジェクトへのリンクが出ます。この行は最後のバッチに並びます。確定すると、この行は作らずに完了になります（見積もりにも含みません）。確定までにそのプロジェクトを削除したときは、行は作られます。
- それでも作り直したいときは、編集画面で「作り直す」にチェックを入れて保存します。自動の順序の計画では、その行を入れてもう一度並べます。この選択は行に残り、下書きを作り直しても「既存」には戻りません。チェックを外して保存すると元に戻ります。
- 同じ ROI × TLF の、まだ完成していないプロジェクトがあるときは、注意とリンクが出ます。そのまま確定すると、別に作ります。

### 確定して実行する

- 「確定して開始」を押すと、見積もり（時間と費用）を確かめてから開始します。見積もりは 1 回の実行を約 48 分とし、「種」の行は 1 件ずつ、ほかのバッチは順番に進み、行の 20% に手直しが入るとして計算し、費用は 1 行あたり $0.18〜0.39 です。既存のプロジェクトで済む行は含みません。質問への回答を待つ時間も含みません。
- 同時に実行する数は、管理者が決める全体の上限と 1 人あたりの上限の小さいほうです。OpenAI のレート制限（毎分のトークン数）で待つこともあります。
- 失敗した行は自動で 2 回までやり直します。それでも失敗すると「要対応」になり、「リトライ」か「スキップ」を選べます。ほかの行は進み続けます。
- 計画が作ったプロジェクトは通常のプロジェクトと同じ画面で開けます。ヘッダーに計画へのリンクが出ます。費用は各プロジェクトに記録され、計画の画面には、下書きと再計画のジョブを含めた合計と、そのうち計画用のジョブの費用が出ます。

### バッチごとの見直しと提案

- 自動の順序の計画では、バッチが終わるたびに、まだ始まっていない行を並べ直します。完成したプロジェクトが実際に使った回路のアンカーでその行のアンカーを置き換えてから並べるので、予想と違った重なりも次のバッチに反映されます。始まった行・完了した行・質問中や要対応の行は動きません。
- 続けて、計画用のジョブ（再計画）が、終わった行の結果をもとに変更を提案することがあります。「行の追加」（終わった行が共有する回路で、まだどの行も扱っていないもの）、「行の削除」（終わった行がすでに扱っている、まだ始まっていない行）のどちらかで、理由が付きます。何も提案しないことも多くあります。また、粒度方針を変えることがあります（オーケストレーターが決めるので承認は要りません。すぐに反映され、決定済みの提案に「オーケストレーターが反映」として残ります）。
- 提案は、「承認」するまで計画を変えません。承認すると、行が追加され（自動でバッチに入ります。同じ ROI × TLF の完成したプロジェクトがあれば、作らずに完了になります）、または行がスキップされます。「却下」すると何も変わりません。削除を提案された行がもう始まっているとき、または追加を提案された行と同じ ROI × TLF の行がすでにあるときは、その提案は承認できず「無効」になります。決定済みの提案は、履歴の下にまとめて出ます。
- 再計画のジョブも同時実行数の枠を 1 つ使い、費用が記録されます。枠が空くまで待ち、一時停止中は実行しません。失敗しても計画はそのまま進みます。
- 並べ直しはバッチごとに行いますが、再計画のジョブは 1 つの計画で 10 回ほどまでです。最初のバッチが終わったときに 1 回、そのあとは計画の行の 1 割が終わるごとに 1 回動きます（10 行までの計画ではバッチごと）。同時実行数が 1 だとバッチが 1 行ずつになり、バッチごとにジョブを動かすと行と同じ数だけ費用と待ち時間がかかるためです。
- 手動の順序の計画では、並べ直しも提案もありません。

### Canon と組み合わせる

計画に Canon を 1 つ決めておくと、完成した行をその Canon に取り込みながら進みます。行が「完了」になるのは、その行の PR を人が承認したときです。自動で承認することはありません。

- **Canon を選ぶ**: 下書きの「Canon」で、「なし」「既存の Canon」（自分が所有する Canon から選びます。共同編集者として参加している Canon は選べません）「新しい Canon」（名前の初期値は計画の名前）のどれかを選びます。新しい Canon は、計画を確定したときに、計画の粒度方針で作られます。確定後は変えられず、Canon へのリンクと最新の rev が出ます。
- **作り始め**: 各行のプロジェクトは、作り始めるときに Canon に入り、その時点の最新の rev に固定されます。すでに完成したプロジェクトで済む行は、そのプロジェクトがこの Canon に入っていれば完了、どの Canon にも入っていなければ自分のバッチの番が来たとき（種の PR の承認待ちなども、ほかの行と同じです）に Canon に入れて push し（作り直しはしません）、ほかの Canon に入っていれば「人の判断」になります。
- **push と「承認待ち」**: 行のプロジェクトが完成すると、自動で Canon に push され、行は「承認待ち」になります。行から PR を開けます。種でない行は、ジョブの枠が空いたときに AI レビューも自動で始まります（「AI レビュー待ち」→「AI レビュー実行中」→ 終わると「AI レビュー済み」。押すと PR の画面が開き、レビューの結果が見られます）。AI レビューは指摘を挙げるだけで、判断はしません。AI レビューの費用は、計画の費用に含まれます。要確認の項目は、いつも人が判断します。
- **Canon に合わせた更新**: PR に Canon とのエラーの矛盾があり、その原因が「作り始めたあとに Canon が新しい rev に進んだこと」のときは、プロジェクトを最新の rev に固定し直し、「Canon rev N に合わせて更新」という追加の指示を自動で送ります（ジョブの枠が空いてから）。枠を待っている間は、行に PR へのリンクと「Canon に合わせた更新を待っています」が出ます。その間に Canon で PR を承認すると行は完了になり、却下すると「人の判断」になります（どちらの場合も追加の指示は送りません）。完成すると、もう一度 push します。この更新は 1 行につき 2 回までで、行に「Canon に合わせた更新 1/2」のように出ます。
- **人の判断**: 2 回更新しても矛盾が残る、Canon が進んでいないのに矛盾がある、PR が却下された・取り下げられた、プロジェクトがほかの Canon に入っている、push できなかった、のどれかのときは、行が「人の判断」になり、理由が出ます。PR を確かめてから、「完了にする」（PR はそのまま残り、自動では取り込まれません）、「もう一度 push」（完成したプロジェクトだけ。計画の次の処理で push します）、「スキップ」のどれかを選びます。「人の判断」の行の PR を Canon で承認した場合も、行は自動で完了になります。
- **種の PR**: 種の行は 1 件ずつ作り、それぞれの PR を人が承認するまで、次の種もほかのバッチも始まりません。待っている間は「種の PR の承認を待っています」と PR へのリンクが出ます。種の行が「人の判断」になったときも同じように止まり、「種の行に人の判断が必要です」とその行へのリンクが出ます。種の PR を先に承認すると、あとの行はその rev から作り始めます。再計画（自動の順番）は、バッチの行の PR がすべて承認されてから行います。
- **承認待ちが多いとき**: 計画の「承認待ち」の PR が 20 件になると、新しいバッチを始めません（「承認待ちの PR が 20 件あるため、次のバッチを止めています」）。いまのバッチの行は続きます。承認が進むと次のバッチが始まります。Canon の画面の「まとめて承認」を使うと、矛盾の無い PR をまとめて承認できます。
- **PR から計画へ**: 計画が push した PR には、Canon の PR の一覧と PR の画面に計画の ID が出ます。Canon の所有者は、そこから計画を開けます。
- **費用**: AI レビューと「Canon に合わせた更新」は、どちらも通常のジョブです。同時実行数の枠を 1 つ使い、枠が空くまで待ち、費用が記録されます。
- 計画は、すべての行が「完了」か「スキップ」になったときに完了します。「承認待ち」や「人の判断」の行が残っている間は完了しません。

### 質問箱

エージェントが質問すると、その行だけが止まり、計画の画面の「質問箱」に質問が出ます。答えるとその行が再開します。ほかの行は止まりません。プロジェクトの画面で答えてもかまいません。

### 一時停止・再開・中止

- **一時停止**: 新しい行を始めません。実行中の行はそのまま続きます。Canon のある計画では、完成した行の push と PR の承認の反映も続きます。API キーが使えなくなったときや、計画の Canon が見つからなくなった（削除された）ときは、計画が自分で一時停止し、理由が表示されます。Canon が見つからないときは、承認待ちの行と、完成して push するはずだった行が「人の判断」になります。
- **再開**: 止まったところから続けます。完了した行は作り直しません。
- **中止**: 実行中のジョブを止め、新しい行を始めません。中止した計画も再開できます（止めた行は続きから作ります）。「承認待ち」と「人の判断」の行と、その PR はそのまま残ります（中止したあとも Canon で承認できます）。
- 下書き・完了・中止の計画は削除できます（下書き作成中は、取り消してから削除します）。作られたプロジェクトは残ります。

## 公開と複製

- プロジェクト（成果物があるもの）と Canon は、ヘッダーのボタンで「公開」にでき、いつでも非公開に戻せます。
- 公開したものは、ログインした誰でも「公開ライブラリ」で見られます。エージェントの履歴・費用・メールアドレスは公開されません。
- 公開プロジェクトは「複製」で自分の非公開プロジェクトにできます（HCD・FRG・表データ・レポート・解説記事が写ります）。元のプロジェクトは変わりません。BRA xlsx は追加の指示で作り直されます。
- 公開した Canon には、ほかのユーザーが自分の Canon から PR を送れます。承認するのは所有者です。

## 設定

サイドバーの「設定」で次のものを変えられます。

- **OpenAI API キー**: 登録・更新・削除と、デフォルトの API キーの利用状況
- **プロフィール**: 表示名と Contributor 名（Project.csv と xlsx に記録されます。英語表記を推奨します）
- **既定のモデル / reasoning effort**: 新しいプロジェクトの初期値
- **新しいプロジェクトの既定の Canon**
- **パスワード変更**

表示の言語とテーマ（ライト・ダーク）は、サイドバーの下で切り替えます。アプリの変更点は、サイドバーの一番下にあるバージョン番号を押すとリリースノートで確かめられます。

## 困ったとき

### 実行できない

「OpenAI API キーが未登録です」と出る場合は、設定画面で自分のキーを登録するか、管理者にデフォルトの API キーの利用承認を依頼してください（[API キーを用意する](#api-キーを用意する)）。

### 使いたいモデルが一覧に無い

デフォルトの API キーで実行する場合、一覧には使えるモデルだけが出ます。ほかのモデルを使うには、自分のキーを登録してください。

### 長い時間止まっているように見える

エージェント欄の最後の行に、作業中のステップと経過時間が出ます。状態が「回答待ち」なら、質問に答えると再開します。「失敗」「中止」なら「続きからリトライ」を押してください。

### 費用はどこで見る

ヘッダーの利用量を押すと、ジョブごとのトークンと推定料金が出ます。「プロジェクト一覧」には全プロジェクトの合計が出ます。料金は OpenAI の公開単価から計算した推定値で、実際の請求額は OpenAI のダッシュボードで確かめてください。

### 結果を直したい

完了したプロジェクトなら、エージェント欄から追加の指示を送ります。最初からやり直す場合は、新しいプロジェクトを作ってください。

### ほかの人に見せたい

プロジェクトを公開すると、ログインした人が「公開ライブラリ」で見られます（[公開と複製](#公開と複製)）。

# ステップ4: 機能詳細の定義

## 目的

TLFおよび各GN（第2階層・第3階層）の機能を詳細に定義する。各ノードについて、A1. Requirement、A2. Requirement realization by interface、B1. Capability、B2. Mechanism、B3. Implementationを記述する。

---

## TLF（Top Level Function）の機能詳細

### TLF: DeductiveReasoning

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | 一般的な論理規則を特定の前提に適用し、論理的に妥当な結論を導出する。入力として前提情報（視覚的・言語的）を受け取り、出力として論理的に整合した結論を生成する。前提から結論への変換が論理的推論規則に従って行われることを保証する。 |
| **A2. Requirement realization by interface** | 5つの第2階層GN（PremiseRepresentation, RuleSelection, RuleApplication, ConclusionGeneration, ResponseExecution）の組み合わせにより実現される。前提が内部表現として構築され（PremiseRepresentation）、適切なルールが選択され（RuleSelection）、そのルールが前提に適用され（RuleApplication）、結論が生成され（ConclusionGeneration）、外部に出力される（ResponseExecution）という一連のプロセスにより、演繹的推論が完遂される。 |
| **B1. Capability** | 構造化された入力情報に対して、あらかじめ定義された変換規則を適用し、規則に従った出力を生成する。変換規則の適用が論理的整合性を保つことを保証する一般的な規則ベース推論システム。 |
| **B2. Mechanism** | 入力情報を内部表現に変換し、変換規則データベースから適切な規則を選択し、選択された規則を内部表現に適用して新しい内部表現を生成し、生成された表現を検証して出力形式に変換する。各段階で情報の整合性がチェックされ、エラーが検出された場合は前の段階にフィードバックされる。 |
| **B3. Implementation** | 入力: $P = \{p_1, p_2, ..., p_n\}$ (前提集合)<br/>内部表現構築: $\mathcal{R}_{internal} = f_{represent}(P)$<br/>規則選択: $r^* = \arg\max_{r \in \mathcal{R}_{rules}} \text{applicability}(r, \mathcal{R}_{internal})$<br/>規則適用: $\mathcal{R}_{new} = r^*(\mathcal{R}_{internal})$<br/>結論生成: $C = f_{conclude}(\mathcal{R}_{new})$<br/>妥当性制約: $\text{valid}(C \mid P, r^*) = \text{true}$<br/>出力: $O = f_{execute}(C)$ |

## 第2階層GNの機能詳細

### GN: PremiseRepresentation

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | 外部から提示された前提情報（視覚的・言語的）を理解し、推論に利用可能な内部表現として構築する。意味的表現、空間的表現、作業記憶表現の3つの形式で前提を保持し、後続の推論プロセスで利用可能にする。 |
| **A2. Requirement realization by interface** | 4つの第3階層GN（SemanticParsing, VisuospatialIntegration, SpatialRepresentation, WorkingMemoryMaintenance）により実現される。意味内容が解析され（SemanticParsing）、視覚情報が統合され（VisuospatialIntegration）、空間的表現が構築され（SpatialRepresentation）、これらが作業記憶に保持される（WorkingMemoryMaintenance）。 |
| **B1. Capability** | 多様な形式の入力情報を、複数の内部表現形式（記号的、空間的、一時的記憶）に変換し、並行して保持する。各表現形式は独立してアクセス可能であり、相互に参照可能である。 |
| **B2. Mechanism** | 入力情報を並行して複数の処理パスに分配する。各パスは異なる表現形式を生成する（意味的、空間的、記憶的）。生成された表現は共通のバッファに格納され、表現間のリンクが確立される。バッファの内容は持続的活動により維持され、必要に応じて更新される。 |
| **B3. Implementation** | 入力: $I = \{I_{semantic}, I_{visual}\}$<br/>意味表現: $R_{sem} = f_{semantic}(I_{semantic})$<br/>空間表現: $R_{spatial} = f_{spatial}(I_{visual})$<br/>統合表現: $R_{integrated} = f_{integrate}(R_{sem}, R_{spatial})$<br/>作業記憶: $WM(t) = \{R_{sem}(t), R_{spatial}(t), R_{integrated}(t)\}$<br/>維持: $WM(t+1) = (1-\lambda) \cdot WM(t) + \lambda \cdot WM_{new}(t)$ |

### GN: RuleSelection

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | 構築された前提表現に基づき、適用可能な論理的ルールを長期記憶から検索し、最も適合するルールを選択する。選択されたルールは、前提パターンと適合し、目標とする結論に到達可能なものである。 |
| **A2. Requirement realization by interface** | 第3階層のRuleSelectionProcessにより実現される。ルールの検索、前提とのマッチング評価、最適ルールの選択が統合的に実行される。L-IFGがルールデータベースへのアクセスを担い、L-Caudateが選択の強化学習的調整を担う。 |
| **B1. Capability** | パターンマッチングによるデータベース検索と、マッチング度に基づく選択を実行する。検索空間が大きい場合でも、ヒューリスティックにより効率的に絞り込む。 |
| **B2. Mechanism** | 前提表現から特徴パターンを抽出し、ルールデータベース内の各ルールの条件部と比較する。マッチング度を計算し、上位候補を選択する。候補間での競合解決により、最終的に1つのルールを選択する。選択プロセスは強化学習により調整され、過去の成功経験がバイアスとなる。 |
| **B3. Implementation** | 前提表現: $R_{premise}$<br/>パターン抽出: $P = f_{pattern}(R_{premise})$<br/>マッチング度: $M_i = \text{match}(P, \text{rule}_i)$ for all $i$<br/>候補選択: $\text{candidates} = \{\text{rule}_i \mid M_i > \theta_{match}\}$<br/>競合解決: $r^* = \arg\max_{r \in \text{candidates}} [M_i + \alpha \cdot \text{history}(r_i)]$<br/>ここで、$\text{history}(r_i)$は過去の成功率、$\alpha$は学習係数 |

### GN: RuleApplication

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | 選択されたルールを前提表現に適用し、論理的推論を実行する。複数の前提を統合し、ルールの条件部が満たされることを確認し、ルールの結論部を導出する。推論プロセス全体を制御し、必要に応じて調整する。 |
| **A2. Requirement realization by interface** | 2つの第3階層GN（ExecutiveControl, LogicalInference）により実現される。実行制御がプロセス全体を監視・調整し（ExecutiveControl）、論理的推論が実際にルールを適用する（LogicalInference）。両者の協調により、適切で効率的な推論実行が保証される。 |
| **B1. Capability** | 条件付き変換規則を適用し、入力パターンから出力パターンへの変換を実行する。変換プロセスを監視し、エラーや矛盾を検出した場合は修正または中断する。 |
| **B2. Mechanism** | ルールの条件部と前提表現を照合し、条件が満たされることを確認する。条件が満たされる場合、ルールの結論部を前提表現に統合し、新しい内部表現を生成する。推論プロセス全体は実行制御モジュールにより監視され、各ステップの妥当性がチェックされる。異常が検出された場合、プロセスは中断または修正される。 |
| **B3. Implementation** | 入力: $R_{premise}$, $r^*$ (選択されたルール)<br/>条件照合: $\text{cond\_met} = \text{check}(r^*_{condition}, R_{premise})$<br/>If $\text{cond\_met}$:<br/>　推論実行: $R_{new} = \text{apply}(r^*_{conclusion}, R_{premise})$<br/>　妥当性チェック: $\text{valid} = \text{verify}(R_{new}, R_{premise})$<br/>Else:<br/>　エラー処理: $R_{new} = \text{error\_handle}(r^*, R_{premise})$<br/>出力: $R_{inference} = R_{new}$ if $\text{valid}$ else $\text{retry}$ |

### GN: ConclusionGeneration

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | 推論プロセスの結果を受け取り、論理的に妥当な結論として定式化する。推論結果の論理的整合性を検証し、明示的な結論文として表現する。矛盾や不完全性が検出された場合は、前段階にフィードバックする。 |
| **A2. Requirement realization by interface** | 第3階層のConclusionFormulationにより実現される。推論結果の検証と定式化が統合的に実行される。L-AGが推論結果を統合し、L-IFGが言語的な結論文として定式化する。 |
| **B1. Capability** | 内部表現を検証し、論理的整合性を確認した上で、外部出力可能な形式に変換する。検証に失敗した場合は、エラー信号を生成し、修正を促す。 |
| **B2. Mechanism** | 推論結果の内部表現を受け取り、論理的制約（無矛盾性、完全性）を満たすかチェックする。制約が満たされる場合、結論を明示的な言語表現に変換する。制約が満たされない場合、エラー信号を生成し、推論プロセスを再実行するよう要求する。 |
| **B3. Implementation** | 入力: $R_{inference}$<br/>整合性検証: $\text{consistent} = \text{check\_consistency}(R_{inference}, R_{premise})$<br/>完全性検証: $\text{complete} = \text{check\_completeness}(R_{inference})$<br/>If $\text{consistent} \land \text{complete}$:<br/>　結論定式化: $C = f_{formulate}(R_{inference})$<br/>Else:<br/>　エラー信号: $E = \text{generate\_error}(R_{inference})$<br/>　フィードバック: $\text{feedback}(E) \rightarrow \text{RuleApplication}$<br/>出力: $C$ or $E$ |

### GN: ResponseExecution

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | 生成された結論を外部環境に出力するための運動プログラムに変換し、適切なタイミングで実行する。結論の内容に応じた具体的な応答（言語的、行動的）を準備し、実行する。 |
| **A2. Requirement realization by interface** | 第3階層のMotorProgrammingにより実現される。結論が運動プログラムに変換され、タイミング制御とともに実行される。L-PMCが運動プログラムを準備し、L-Putamenが決定戦略の実行を調整する。 |
| **B1. Capability** | 抽象的な内部表現を具体的な運動コマンドに変換し、実行タイミングを制御する。複数の応答候補から適切なものを選択し、実行する。 |
| **B2. Mechanism** | 結論の内部表現を運動パラメータ空間にマッピングする。複数の可能な運動プログラムが準備され、文脈や課題要求に応じて最適なものが選択される。選択された運動プログラムは、適切なタイミング信号により実行される。実行は段階的に進行し、フィードバックにより調整される。 |
| **B3. Implementation** | 入力: $C$ (結論)<br/>運動マッピング: $M = \{m_1, m_2, ..., m_k\} = f_{motor\_map}(C)$<br/>選択: $m^* = \arg\max_i [\text{appropriateness}(m_i, \text{context})]$<br/>タイミング制御: $t_{exec} = f_{timing}(\text{task\_state})$<br/>実行: If $t_{current} \geq t_{exec}$:<br/>　$O_{motor}(t) = m^*(t)$<br/>出力: $O_{motor}$ |

## 第3階層GNの機能詳細

### GN: SemanticParsing

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | 言語的に提示された前提の意味内容を解析し、命題的な意味表現を構築する。単語、句、文の意味を解析し、前提間の論理的関係を抽出する。 |
| **A2. Requirement realization by interface** | L-IFGとL-AGの協調により実現される。L-IFGが言語的な意味解析を担当し、L-AGが意味的関係の統合を担当する。両UCの出力が統合されることで、前提の完全な意味表現が構築される。 |
| **B1. Capability** | 記号列（単語列）を意味的な構造表現に変換する。構文解析と意味解析を統合し、命題レベルの表現を生成する。 |
| **B2. Mechanism** | 入力文を単語に分割し、各単語の意味を長期記憶から検索する。単語間の統語的関係を解析し、句構造を構築する。句の意味を合成し、文全体の命題表現を生成する。複数の前提がある場合、前提間の関係を抽出する。 |
| **B3. Implementation** | 入力: $S = \{w_1, w_2, ..., w_n\}$ (単語列)<br/>意味検索: $\text{sem}_i = \text{lexicon}(w_i)$<br/>統語解析: $\text{tree} = \text{parse}(S)$<br/>意味合成: $\text{prop} = \text{compose}(\text{sem}_1, ..., \text{sem}_n, \text{tree})$<br/>出力: $R_{semantic} = \text{prop}$ |

### GN: VisuospatialIntegration

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | 視覚的に提示された情報を統合し、視空間的なイメージを生成する。視覚特徴（位置、形状、色など）を統合し、自己中心的な視空間表現を構築する。 |
| **A2. Requirement realization by interface** | L-SPLとL-Precuneusの協調により実現される。L-SPLが視覚特徴を統合し、L-Precuneusが主観的視点からの空間イメージを生成する。両UCの出力により、推論に利用可能な視空間表現が得られる。 |
| **B1. Capability** | 複数の視覚特徴ストリームを統合し、統一された空間表現を生成する。自己中心座標系における空間配置を構築する。 |
| **B2. Mechanism** | 背側視覚経路からの複数の特徴（位置、運動、大きさなど）を受け取り、共通の参照フレーム（自己中心座標系）に変換する。各特徴を重み付けして統合する。統合された表現に対して、心的回転などの内的操作を適用可能にする。 |
| **B3. Implementation** | 入力: $V = \{V_{pos}, V_{motion}, V_{size}, ...\}$<br/>座標変換: $V'_{feat} = T_{ego}(V_{feat})$<br/>重み付け統合: $I(x,y,z) = \sum_{feat} w_{feat} \cdot V'_{feat}(x,y,z)$<br/>出力: $R_{visuospatial} = I$ |

### GN: SpatialRepresentation

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | 統合された視空間情報を、推論に利用可能な空間座標系として表現し、心的モデルに統合する。要素間の空間的関係（左右、上下、順序など）を明示的に表現する。 |
| **A2. Requirement realization by interface** | L-IPSとL-AGの協調により実現される。L-IPSが空間座標系を提供し、L-AGが心的モデルとして統合する。両UCの相互作用により、空間的関係が推論に利用可能になる。 |
| **B1. Capability** | 空間情報を離散的または連続的な座標系に投影し、要素間の関係を計算可能な形式で表現する。推移的推論などの空間的操作を可能にする。 |
| **B2. Mechanism** | 視空間イメージから要素の位置を抽出し、座標値として表現する。要素間の距離や順序を計算し、関係行列として保存する。この表現は地誌的な神経マップとして実装され、持続的活動により維持される。 |
| **B3. Implementation** | 入力: $R_{visuospatial}$<br/>要素抽出: $E = \{e_1, e_2, ..., e_m\}$<br/>座標割り当て: $X_i = (x_i, y_i, z_i)$ for each $e_i$<br/>関係計算: $Rel_{ij} = f_{relation}(X_i, X_j)$<br/>出力: $R_{spatial} = \{E, X, Rel\}$ |

### GN: WorkingMemoryMaintenance

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | 構築された前提表現を作業記憶として一時的に保持し、推論プロセス全体を通じて維持する。表現の減衰を防ぎ、必要に応じて更新する。 |
| **A2. Requirement realization by interface** | L-DLPFCとL-IPSの協調により実現される。L-DLPFCが抽象的・意味的情報を保持し、L-IPSが空間的情報を保持する。両UCの持続的活動により、多様な情報が並行して維持される。 |
| **B1. Capability** | 複数の情報を並行して短期間保持し、減衰を防ぐ。保持された情報に選択的にアクセスし、必要に応じて更新する。 |
| **B2. Mechanism** | 入力された情報を複数の独立したバッファに格納する。各バッファの内容は神経活動の持続により維持される。注意機構により、特定のバッファの活動が選択的に増強される。バッファの内容は徐々に減衰するが、リハーサルにより再活性化される。 |
| **B3. Implementation** | バッファ状態: $WM(t) = \{w_1(t), w_2(t), ..., w_k(t)\}$<br/>減衰: $w_i(t+\Delta t) = w_i(t) \cdot e^{-\Delta t / \tau}$<br/>リハーサル: $w_i(t) \leftarrow w_i(t) + \beta \cdot \text{rehearsal}_i(t)$<br/>注意増強: $w_i(t) \leftarrow w_i(t) \cdot (1 + \alpha \cdot A_i(t))$<br/>出力: $WM(t)$ |

### GN: RuleSelectionProcess

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | 長期記憶からルールを検索し、前提パターンとの適合性を評価し、最適なルールを選択する。検索、マッチング、選択の一連のプロセスを統合的に実行する。 |
| **A2. Requirement realization by interface** | L-IFGとL-Caudateの協調により実現される。L-IFGがルールデータベースへのアクセスとマッチング評価を担当し、L-Caudateが選択の強化学習的調整を担当する。 |
| **B1. Capability** | パターンマッチングによる検索と、評価関数に基づく選択を統合的に実行する。競合する候補から最適解を選ぶ競合解決メカニズム。 |
| **B2. Mechanism** | 前提表現から特徴を抽出し、ルールデータベース内の各ルールと比較する。マッチング度を計算し、閾値を超えたルールを候補とする。候補間で競合が生じた場合、過去の成功経験やコンテキストに基づいて重み付けし、最も高い評価を得たルールを選択する。 |
| **B3. Implementation** | 前提: $R_{premise}$<br/>特徴抽出: $F = f_{feature}(R_{premise})$<br/>候補生成: $\mathcal{C} = \{r_i \mid \text{match}(F, r_i) > \theta\}$<br/>評価: $\text{score}(r_i) = \text{match}(F, r_i) + \alpha \cdot \text{history}(r_i) + \beta \cdot \text{context}(r_i)$<br/>選択: $r^* = \arg\max_{r \in \mathcal{C}} \text{score}(r)$ |

### GN: ExecutiveControl

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | ルール適用プロセス全体を監視し、各ステップの妥当性をチェックし、必要に応じて修正や再実行を指示する。エラーや矛盾を検出し、適切な対処を行う。 |
| **A2. Requirement realization by interface** | L-DLPFCとL-MeFGの協調により実現される。L-DLPFCが実行プロセスの状態を監視し、L-MeFGが全体的な認知制御信号を生成する。両UCの統合により、柔軟で堅牢な実行制御が実現される。 |
| **B1. Capability** | プロセスの状態を監視し、目標との差異を検出し、修正アクションを生成する。フィードバック制御により、プロセスを目標状態に収束させる。 |
| **B2. Mechanism** | 現在のプロセス状態と目標状態を比較し、差異（エラー信号）を計算する。エラー信号が閾値を超えた場合、制御信号を生成し、プロセスパラメータを調整する。調整により状態が改善されない場合、プロセスを中断し、再計画を促す。 |
| **B3. Implementation** | 現在状態: $S_{current}$, 目標状態: $S_{goal}$<br/>エラー計算: $E = \|S_{goal} - S_{current}\|$<br/>If $E > \theta_{error}$:<br/>　制御信号: $C = \kappa \cdot E$<br/>　調整: $S_{current} \leftarrow S_{current} + C \cdot \Delta t$<br/>If $E > \theta_{critical}$:<br/>　中断: $\text{interrupt}()$<br/>出力: $C$ or $\text{interrupt}$ |

### GN: LogicalInference

| 項目 | 内容 |
|------|------|
| **A1. Requirement** | 複数の前提を統合し、選択されたルールに基づいて論理的推論を実行する。ルールの条件部が前提により満たされることを確認し、ルールの結論部を導出する。 |

## まとめ

TLF、5つの第2階層GN、9つの第3階層GNについて、A1. Requirement、A2. Requirement realization by interface、B1. Capability、B2. Mechanism、B3. Implementationを定義した。

各ノードの機能は階層的に整合しており、子ノードの組み合わせにより親ノードの機能が実現されることが確認された。また、UCレベルの実装（HCDで定義済み）との整合性も保たれている。
